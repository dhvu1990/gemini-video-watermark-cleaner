# v1.0.18 - Edge Finishing Pass

Date: 2026-08-15
Branch: `agent/v1.0.18`
Base: `main` after v1.0.17 (`68777ad19f8dbfe3015060ba7faf21ac6feeb9a3`)

## User validation that triggered this release

Real-video testing of v1.0.17 showed the cleanup was already close to the desired result:

- detector geometry remained correct;
- restored core texture was preserved well;
- subpixel calibration did not need to move the alpha map on the tested sample (`Offset X = 0.00`, `Offset Y = 0.00`);
- the remaining defect was a thin, low-amplitude diamond outline rather than a broad watermark body artifact.

The user explicitly requested one more quality pass focused on the remaining edge while keeping the improved core detail.

## Release goal

Do not change detector geometry, body calibration, subpixel registration, atlas behavior, or core restoration.

Add only a narrow finishing stage that:

1. targets the strongest residual edge-ring pixels;
2. uses the already validated alpha-gradient normal direction;
3. bridges between an outer clean-background anchor and an inner restored anchor;
4. backs off on real scene structure;
5. caps the correction strongly enough that the high-alpha core remains visually unchanged.

## Implementation

### `src/video/edgeBridge.js`

Added exported helper:

`applyMicroEdgeFinish(image, alphaMap, strength = 0.48)`

The pass runs after the existing `applyNormalEdgeBridge()` correction.

Key constraints:

- edge mask weight: strong emphasis on `edge`, light use of `feather`, explicit suppression by `core`;
- skip high-alpha core when `core > 0.46`;
- require meaningful alpha gradient (`> 0.0018`);
- use short-radius normal-direction anchors (`<= 6.5 px`);
- require a residual mismatch before applying correction;
- structure guard becomes strong when inner and outer anchors disagree;
- long bridge spans are reduced;
- final blend is capped at `0.52`;
- per-channel correction is capped at `±32` intensity levels.

The result reports:

- `finishingPixels`
- `finishingMeanBlend`

These are nested into the existing `edgeBridge` diagnostics so the preview/export path stays unified.

## Why this is different from prior cleanup stages

This is intentionally not another blur, atlas pass, or body alpha adjustment.

v1.0.18 assumes v1.0.17 already solved the broad footprint well. The new pass only corrects the final narrow edge mismatch when the current pixel still differs from the color predicted by the two normal-direction anchors.

## Regression protection

`tests/edgeBridge.test.mjs` was extended with a dedicated micro-finishing test.

The synthetic case contains:

- a textured high-alpha core that must remain effectively unchanged;
- a thin dark edge artifact around the diamond;
- a clean reference background.

The test requires:

- at least one finishing pixel to be selected;
- edge-region error after finishing to be lower than before finishing;
- mean core change to remain below `0.75` intensity levels.

Existing tests for the main edge bridge and strong real-structure protection remain active.

## Real-video acceptance criteria

Compare against the same keyboard/laptop sample used for v1.0.17:

- core texture should remain as clear as v1.0.17;
- residual diamond outline should become thinner or lower contrast;
- no new blur patch should appear;
- no real keyboard edge should be visibly bent or erased;
- result preview and full exported video should remain consistent.
