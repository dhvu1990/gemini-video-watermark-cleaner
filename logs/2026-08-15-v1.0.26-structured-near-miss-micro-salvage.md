# v1.0.26 — Structured Near-Miss Micro-Salvage

Date: 2026-08-15

## Motivation

Real-video validation of v1.0.25 confirmed that the adaptive background split is behaving correctly:

- the USB-C sample enters the safe empty-zone / smooth branch and is already visually near-clean,
- the keyboard sample remains `structured`, which protects its real texture and object edges from aggressive reconstruction.

The structured sample also exposed a useful diagnostic pattern:

- final structured result: about `1.455` total residual,
- primary structured candidate: about `1.464` total residual,
- the candidate was correctly rejected because it was slightly worse.

That difference is only about 0.6%, so the failure is not evidence that the structured geometry is entirely wrong. It suggests that the full structured-ring pass may be slightly too strong for a subset of near-miss frames.

## Goal

Add a conservative salvage path for structured candidates that narrowly miss the existing acceptance gate.

The salvage path must:

1. never run on `smooth-rebuild` or `empty-hard-rebuild`,
2. only run after the normal structured candidate was rejected,
3. only run when the rejected candidate is still close to the incoming result,
4. use a much smaller cleanup strength,
5. accept only when the actual post-clean residual improves,
6. preserve the exact incoming v1.0.25 output if the micro candidate is not better.

## Implementation

File changed:

`src/video/structuredRingSuppress.js`

### Existing primary pass remains unchanged

The v1.0.25 primary structured-ring pass still runs first with the existing default strength of `0.50` and existing geometry/structure guards.

Its existing acceptance conditions are still evaluated first.

### New near-miss gate

The micro-salvage path is considered only when:

- the primary structured pass was rejected,
- the primary pass actually modified candidate pixels,
- candidate total residual is within `1.025x` of the incoming result by default,
- candidate luma residual is within `1.025x` of the incoming result.

This directly covers real cases such as `1.464 / 1.455 ~= 1.006` while excluding clearly bad primary candidates.

### Micro strength

The salvage candidate reuses the same structure-aware ring geometry, but at a much lower strength:

- default scale: `35%` of the primary structured strength,
- bounded to approximately `0.08 .. 0.26`.

No whole-ROI blur is introduced.

### Salvage acceptance

The micro candidate is accepted only when all of the following remain safe:

- final total residual <= `0.998x` incoming total residual,
- final luma residual <= `1.002x` incoming luma residual,
- final chroma residual <= `1.01x` incoming chroma residual,
- shape-aligned structured-ring score <= `1.003x` incoming score,
- and either total residual improves by at least about `0.2%` or shape-aligned residual improves by at least about `0.8%`.

If those conditions fail, the output remains exactly the incoming structured result.

## Diagnostics

`structuredRing` now exposes:

- `acceptedMode`: `primary`, `micro-salvage`, or `none`,
- `salvageAttempted`,
- `salvageAccepted`,
- `salvageCandidateAfter`,
- `salvageCandidateAlignedAfter`,
- `salvageCandidatePixels`,
- `salvageNearMissRatio`.

The Tune diagnostics UI reports:

- `YES (micro)` when micro-salvage is accepted,
- `NO (micro tried)` when it was attempted but rejected,
- the micro candidate residual when a salvage attempt exists.

## Regression coverage

`tests/structuredRingSuppress.test.mjs` now checks:

1. structured suppression still never returns a materially worse accepted result,
2. micro-salvage metadata remains present and internally consistent,
3. if a micro candidate is accepted, its final total/luma residual must satisfy the strict safety gates,
4. low-residual regions still skip structured suppression,
5. smooth/empty-hard paths do not run structured suppression.

## Safety principles

- Do not make the structured primary pass globally stronger.
- Do not blur structured texture globally.
- Do not touch the successful USB-C empty-zone path.
- Treat near-miss salvage as an optional candidate, never a mandatory rewrite.
- Always preserve the previous result when the measured candidate is not better.

## Expected real-video behavior

### USB-C / empty background

Expected to behave exactly like v1.0.25:

- `empty-hard-rebuild` or `smooth-rebuild`,
- structured suppression not attempted,
- no regression from the new structured salvage logic.

### Keyboard / structured background

Expected behavior:

- primary structured candidate is attempted first,
- if it is again a near miss similar to `1.464` versus `1.455`, micro-salvage is attempted,
- UI should show either `YES (micro)` if the weaker candidate actually improves measured residual, or `NO (micro tried)` if it does not,
- output is never allowed to become materially worse than the v1.0.25 structured result.
