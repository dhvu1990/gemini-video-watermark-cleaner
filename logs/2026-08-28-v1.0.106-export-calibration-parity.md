## Purpose

Fix a confirmed preview/export calibration-parity gap discovered during real-video validation of v1.0.105. The preview could use the detector's refined alpha geometry and calibrated gain while batch/single-video export reused only the public ROI and rebuilt a generic alpha profile. As a result, a visibly improved preview did not imply improved exported pixels.

This release remains limited to cleanup of the visible Gemini/Veo overlay in user-owned or authorized media. It does not target SynthID or other invisible provenance systems.

## Root cause in v1.0.105

The relevant runtime paths are shared at the restoration stage but not at the detector-calibration handoff:

1. `inspectVideo()` builds the preview with the detector's refined `internalDetection.alphaMap` and detector-calibrated `alphaGain`.
2. `prepareInspectResultForWorker()` deliberately strips private detector state except for the alpha map needed by preview diagnostics.
3. Batch UI stores the public detection and preview but does not persist the private detector calibration for export.
4. Batch `processOptions()` passes `detectedRegion` and the global UI alpha-gain setting, whose default is `1.0`.
5. When `cleanVideo()` receives a `detectedRegion`, it obtains its alpha map through `getVideoAlphaMap(position.width)` rather than directly using `analysis.internalDetection.alphaMap`.
6. `src/video/alpha.js` already contained an `ACTIVE_CALIBRATION` override mechanism, but no production caller activated it for export.

This created the observed parity failure: scene3 could visibly enter `Outline residual escalation` in preview, while the exported H.264 pixels remained byte-for-byte identical to v1.0.104.

## v1.0.106 implementation

### 1. Per-file detector calibration cache inside the worker

New module: `src/video/exportCalibrationCache.js`.

After each successful inspect operation, the worker stores a bounded per-file calibration record containing:

- refined `alphaMap`,
- detector-calibrated `alphaGain`,
- detected position,
- candidate ID.

The cache key uses file identity fields (`name`, `size`, `lastModified`, `type`) and requires the export's detected region to exactly match the cached detected position before calibration can be reused.

This is intentionally per-file. Six portrait videos may all use a 72x72 watermark ROI; calibration from one file must never leak into another simply because the ROI size matches.

### 2. Activate refined alpha only for the scoped export

`src/video/alpha.js` now exposes `clearActiveAlphaCalibration()` so the pre-existing active-calibration mechanism can be safely scoped.

Immediately before an auto-detected export, the worker:

1. clears any prior active calibration,
2. activates the matching per-file refined alpha map with `setActiveAlphaCalibration()`,
3. runs the existing `cleanVideo()` path unchanged,
4. clears active calibration in a `finally` block.

`cleanVideo()` still calls `getVideoAlphaMap(position.width)` for a detected region; that existing function now receives the scoped refined alpha through its pre-existing active-calibration hook. No restoration architecture is replaced.

Manual-region export remains on the generic/manual alpha path and does not consume cached auto-detection calibration.

### 3. Detector gain parity without breaking operator overrides

For batch export, the UI normally sends the global alpha gain default `1.0`. v1.0.106 treats that untouched default as permission to reuse the per-file detector-calibrated gain.

If the operator supplies a non-default gain, that explicit value continues to win. Single-video analysis already writes the detected gain into the UI field, so its existing explicit value is preserved.

### 4. Worker-restart fallback

The normal batch path keeps one worker alive across inspect and process, so cached calibration is reused without repeating detection.

If a transient module/network error causes the worker to be recreated, the private in-worker calibration cache is lost while the page may still retain the public detected ROI. In that case v1.0.106 re-runs inspect only to reconstruct the missing private detector calibration rather than silently falling back to generic alpha and reintroducing preview/export divergence.

A cache-miss re-inspection renders the normal inspect preview internally and can touch adaptive finishing state. The worker therefore resets adaptive finishing state again after calibration restoration and before starting `cleanVideo()`, so the export starts from the same clean per-video temporal/adaptive state as the normal cache-hit path.

### 5. Export diagnostics

Process metadata now records an `exportCalibration` summary indicating whether cached/refreshed detector calibration was reused, along with candidate ID, selected alpha gain and position. The raw alpha map is not included in export metadata.

## Safety properties preserved

This release does **not**:

- lower watermark-detection confidence thresholds,
- lower outline/scene-edge safety gates,
- increase global alpha/body cleanup strength,
- increase blur or reconstruction strength,
- broaden the cleaned ROI,
- remove rollback/acceptance gates,
- change scene-cut temporal reset behavior.

Scene4 remains the hard safety target: real crossing scene structure must remain preserved even if a watermark-like contour is left protected.
