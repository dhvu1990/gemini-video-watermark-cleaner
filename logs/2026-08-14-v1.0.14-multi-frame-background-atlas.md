# v1.0.14 — Multi-frame background atlas

Date: 2026-08-14

## Trigger

Real-video validation of v1.0.13 confirmed that residual-gated analysis worked correctly: the sample with calibration residual around 23 automatically expanded to the full 12-frame scan. However, cleanup quality remained unsatisfactory. The cleaned zoom still showed a strong dark/X-shaped Gemini footprint on a textured keyboard background.

Observed sample characteristics:

- portrait 1080x1920
- detected region around x=864, y=1704, size=72
- detection confidence about 0.77
- full scan confirmed across multiple frames
- calibrated Body gain around 1.00
- residual score around 23.315

Conclusion: single-frame alpha correction plus spatial/directional reconstruction had reached its practical limit for this background. The next release should exploit the fact that this is video and combine information from multiple time-adjacent frames.

## Design goals

1. Keep the validated detector/catalog geometry unchanged.
2. Keep the v1.0.13 residual gate and full-scan escalation.
3. Use a padded ROI so motion can be estimated from clean pixels outside the fixed watermark overlay.
4. Build a bounded history of recent frames instead of relying on one previous donor.
5. Motion-align donors using only low-alpha border pixels.
6. Use median consensus across multiple donors to suppress one-frame residual artifacts.
7. Never force atlas pixels when support is weak.
8. Clear history on scene cuts and skipped frames.
9. Keep preview conservative; allow deeper masked-area consensus only during export when donor frames have already been repaired.

## Implementation

### New module: `src/video/multiFrameRepair.js`

Added:

- `estimateAtlasShift()` — searches a bounded translation window and scores alignment using clean padded-border pixels.
- `buildBackgroundAtlas()` — aligns up to eight recent donors and computes per-pixel median RGB, donor support count, and confidence.
- `applyBackgroundAtlas()` — blends atlas pixels only inside the watermark footprint and only when donor support/confidence passes gates.
- `summarizeAtlas()` — exposes donor count, supported pixel count, and mean confidence for diagnostics.

### Raw donor safety

For detection preview, donors are still raw sampled frames. A raw donor pixel may contribute only when the shifted source coordinate lies outside the watermark alpha footprint. This prevents copying the visible Gemini overlay from one raw frame into another.

### Repaired donor consensus during export

For full-video export, history stores previously repaired padded frames rather than raw watermark frames. In that mode the atlas may also use donor coordinates inside the original watermark footprint, but only when:

- at least three motion-aligned donor frames are available;
- atlas support/confidence gates are met;
- donor alignment improves over the zero-shift baseline.

This allows the median atlas to attack deeper footprint artifacts that could not be reconstructed from only the exterior border.

### Scene safety

The atlas history is cleared when:

- the existing scene-cut detector fires;
- a frame is skipped by the low-confidence gate.

This prevents donors from crossing shots or discontinuities.

### Metadata

Export metadata now records:

- `multiFrameAtlas`
- `atlasFrames`
- `atlasDonorsPeak`
- `historyLimit`

## Tests

Added `tests/multiFrameRepair.test.mjs` covering:

1. translation recovery from clean border pixels;
2. conservative raw-donor behavior;
3. cleaned-donor consensus inside the watermark footprint.

The existing v1.0.13 tests remain part of the release gate.
