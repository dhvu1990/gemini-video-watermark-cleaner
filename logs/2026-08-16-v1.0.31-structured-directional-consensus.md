# v1.0.31 — Structured Directional Consensus Reconstruction

Date: 2026-08-16

## Motivation

Real-video preview validation exposed a repeatable residual pattern after v1.0.30:

- watermark localization is accurate,
- the bright Gemini body is usually removed,
- several structured or piecewise-flat backgrounds retain a faint diamond/triangle ghost,
- a few detailed backgrounds show directional streaks after cleanup.

The existing structured fallback is intentionally conservative. Its narrow ring pass protects real scene edges, but it does not have enough evidence to reconstruct more of the watermark footprint when the local background is simple even though the whole ROI is classified as structured.

## Goal

Add a safe structured reconstruction candidate that uses agreement between several independent clean-background directions instead of trusting one directional donor.

The new candidate must:

1. run only inside the existing structured cleanup path,
2. require at least two two-sided clean-anchor predictions,
3. use a robust median consensus across horizontal, vertical and diagonal directions,
4. reduce confidence when directional predictions disagree,
5. protect genuine high-gradient scene structure,
6. allow moderate core repair only when consensus is strong,
7. use try-and-accept residual gates and preserve the exact previous result when the candidate is not better.

## Implementation

New module:

`src/video/structuredConsensusRepair.js`

For each watermark pixel, the module builds up to four two-sided background predictions:

- horizontal,
- vertical,
- diagonal down-right/up-left,
- diagonal up-right/down-left.

A robust channel-wise median becomes the consensus target. Acceptance strength is then reduced by:

- cross-direction spread,
- clean-anchor disagreement,
- local image gradient,
- long donor span.

Unlike the older early texture repair, the consensus candidate can touch a controlled portion of the high-alpha core, but only when multiple directions agree.

### Candidate-level safety gate

The complete consensus candidate is accepted only when:

- post-clean total residual improves by at least about 0.3%,
- total residual is <= 0.997x the incoming structured result,
- luma residual is <= 1.008x,
- chroma residual is <= 1.008x.

If those gates fail, the incoming image is returned byte-for-byte.

## Structured pipeline integration

`src/video/structuredRingSuppress.js` now runs:

1. structured directional consensus candidate,
2. existing structured ring primary pass,
3. existing near-miss micro-salvage when required.

The ring stages operate on the accepted consensus result. If consensus is rejected, behavior falls back to the previous v1.0.30 structured path.

Diagnostics now include a nested `consensus` object with attempted/accepted state, candidate pixels, core pixels, directional support, spread and residual measurements.

## Regression coverage

New test file:

`tests/structuredConsensusRepair.test.mjs`

Coverage includes:

- accepted candidates must satisfy the strict residual safety gates,
- rejected candidates must preserve the exact input,
- disabled consensus must preserve the exact input,
- conflicting high-detail backgrounds cannot be accepted unless measured residual actually improves safely.

## Version consistency fix

The repository package and worker were already on v1.0.30 while the visible HTML title/badge still displayed v1.0.26. v1.0.31 synchronizes package, worker and visible UI version metadata.

## Expected effect on supplied samples

- black/orange and other broad piecewise-flat backgrounds: fewer faint diamond/triangle ghosts,
- blue rail / graphic backgrounds: only locally consistent regions are reconstructed,
- yellow/blue detailed sample: lower risk of diagonal donor streaks because the new final structured candidate requires directional agreement,
- text/object-heavy samples: conservative behavior is preserved when directions disagree.
