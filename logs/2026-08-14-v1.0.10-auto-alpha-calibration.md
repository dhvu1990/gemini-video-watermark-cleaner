# v1.0.10 — Auto Alpha Shape Calibration

Date: 2026-08-14

## User feedback that triggered this release

Real Gemini/Veo portrait footage was detected correctly at the expected 72x72 location, but the cleaned ROI still showed a clearly visible diamond outline. The interior of the watermark was reduced substantially, which indicated that position detection was no longer the primary problem. The remaining artifact was concentrated in the low-alpha border/curvature region.

Observed example from browser testing:

- 1080x1920 portrait video
- detected region around x=864, y=1704, size=72
- confidence around 0.77 in one test
- vote ratio 1.0
- body alpha gain around 0.89
- visible residual diamond edge after inverse-alpha + edge polish

## Diagnosis

The existing cleanup path used a fixed reference alpha shape resized to the detected region, plus bounded edge enhancement and residual footprint cleanup. That can remove the body of the watermark while leaving the outline when the real watermark differs slightly in edge width, curvature, footprint scale, or edge opacity.

Increasing the global alpha/body gain is not the correct primary fix because it also changes the already-cleaned interior and can create a dark halo. Increasing Edge polish alone can over-blur textured backgrounds.

## v1.0.10 design

The detector geometry remains unchanged. After a high-confidence watermark position is found, the Web Worker now calibrates the alpha shape on up to three sampled ROIs.

The bounded search grid contains 54 combinations:

- profiles: `96-20260520`, `96`
- shape scales: `0.98`, `1.00`, `1.03`
- edge boosts: `0.030`, `0.055`, `0.085`
- edge gains: `1.00`, `1.15`, `1.30`

For each candidate:

1. build the embedded alpha profile at the detected size;
2. apply cleanup edge boost;
3. resample the alpha footprint around its center using the candidate shape scale;
4. apply a separate edge-weighted gain that favors gradient and low-alpha regions;
5. inverse-alpha restore the sampled ROI with the detected body gain;
6. run the existing edge polish/residual cleanup;
7. calculate residual edge energy plus an outside-footprint damage penalty.

The candidate with the lowest residual score is selected.

## Body gain vs Edge gain

- **Body gain** is the existing detected alpha gain. It controls the main watermark opacity and continues to support bounded per-frame adaptive correction during export.
- **Edge gain** is selected by calibration and preferentially strengthens alpha near low-alpha/gradient regions. It is not a second global multiplier over the whole watermark.

This separation is intended to remove more of the outline without over-correcting the watermark body.

## Worker reuse

The chosen calibrated alpha map is stored in the current Web Worker for the detected watermark size. The subsequent full-video export reuses that exact map through the existing `getVideoAlphaMap(size)` path. This avoids a second calibration pass and keeps preview/export consistent.

Detection itself explicitly uses the pinned baseline profile rather than the active calibrated map, so clicking Re-analyze does not create a self-reinforcing detector loop.

## UI

Tune now displays read-only diagnostics:

- selected profile
- shape scale
- edge gain
- edge boost
- residual score

The existing Alpha gain label is renamed to **Body gain**.

## Safety/regression boundaries

- watermark catalog and coordinate detection are not intentionally changed;
- no ML/FDnCNN model is added;
- calibration operates only on the already-detected small ROI;
- export remains local MediaBunny/WebCodecs MP4 processing;
- active calibration is scoped to the current Worker, which is recreated when the source file changes.

## Validation gate

Before merge:

- pinned alpha sync must pass;
- syntax checks must include calibration modules;

- Vite production build must pass;
- after merge, GitHub Pages build and deploy must both succeed.
