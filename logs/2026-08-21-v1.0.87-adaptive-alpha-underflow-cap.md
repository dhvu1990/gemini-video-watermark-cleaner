# v1.0.87 — Adaptive Alpha Underflow Cap

Date: 2026-08-21

## Trigger
Real-video regression batch after v1.0.86 showed scene5 still collapsing into a dark/black diamond-shaped patch. The post-inverse `DarkUnderflowGuard` did not reliably recover the failure because it intentionally required near-black output and multi-direction anchor agreement. Scene5 contains real dark structure around the watermark footprint, so those gates can remain closed even when inverse alpha is already too aggressive.

## Root-cause refinement
The destructive step happens before later finishers: white-overlay inverse alpha can produce negative RGB when calibrated alpha/gain is locally too high. Once values are clamped to zero, later stages have less reliable information and may only partially reconstruct the dark scene.

For observed luma `O`, white overlay alpha `a`, and expected local background floor `B`, inverse restoration should not force the recovered background materially below a conservative local floor. The bound can be expressed as:

`a <= (O - B) / (255 - B)`

v1.0.87 therefore limits effective alpha before inverse RGB clamp, rather than trying to paint over a black patch afterward.

## New module
`src/video/adaptiveAlphaUnderflowCap.js`

### Local evidence
For each medium/high-alpha pixel:
- sample a bounded clean annulus around that pixel;
- only accept samples whose watermark alpha is near zero;
- compute a robust low percentile rather than requiring four directional anchors to agree;
- scale that percentile conservatively to produce a local dark floor.

This is intentionally suitable for dark structured scenes where opposite anchors can disagree but the surrounding clean neighborhood still provides a useful lower-bound estimate.

### Cap behavior
The raw detector alpha remains the starting value. The module computes the maximum alpha that would keep inverse luma at or above the local conservative floor. Effective alpha is reduced only when:
- the requested alpha is in the medium/high-alpha body;
- enough clean annulus samples exist;
- the calculated cap is meaningfully below raw alpha.

Per-pixel reduction is bounded by `maxCapFraction`, preventing a dark scene from being broadly lifted or the watermark from being under-removed everywhere.

### Diagnostics
The stage exposes:
- `attemptedPixels`
- `alphaCappedPixels`
- `rawInverseBlackPixels`
- `cappedInverseBlackPixels`
- `blackPixelsPrevented`
- `meanLocalFloor`
- `meanRawAlpha`
- `meanEffectiveAlpha`
- `coreMeanLumaRaw`
- `coreMeanLumaCapped`
- `coreSamples`

These metrics are specifically intended to stop future scene5 investigation from guessing which stage created the dark collapse.

## Runtime integration
`inverseAlphaRestore()` now:
1. builds an adaptive effective-alpha map from the original ROI;
2. performs inverse alpha using that effective alpha before byte clamping;
3. runs the existing v1.0.86 `DarkUnderflowGuard` as a secondary safety/recovery layer;
4. returns both `adaptiveAlphaUnderflowCap` and `darkUnderflowGuard` diagnostics.

No global structured-ring, shape-ghost, local-tone, outer-halo, protected-rescue, or empty-zone strengths were increased.

## Regression tests
Added `tests/adaptiveAlphaUnderflowCap.test.mjs` covering:
1. over-gained dark background: cap prevents a significant fraction of raw black inverse pixels;
2. `inverseAlphaRestore()` integration: telemetry is exposed and catastrophic black core collapse is avoided;
3. true near-black surrounding background: no broad artificial lift;
4. mixed dark structure: capping remains bounded instead of flattening the footprint.

Existing v1.0.86 dark-underflow tests remain active as the secondary-layer regression suite.

## Safety principle
v1.0.87 does not attempt to reconstruct the entire watermark footprint from neighboring pixels. It only prevents mathematically implausible inverse-alpha dark collapse, keeping later scene-aware repair stages responsible for residual cleanup.
