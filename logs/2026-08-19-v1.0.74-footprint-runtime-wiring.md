# v1.0.74 — Worker-safe Structured Footprint Runtime Wiring

Date: 2026-08-19

## Objective

Fix the preview telemetry path so the five structured-footprint diagnostic fields introduced in v1.0.72 and corrected in v1.0.73 actually receive the alpha map required to calculate the metric after the inspect result crosses the Web Worker boundary.

This release remains diagnostic-only. It does not change watermark cleanup pixels, masks, calibration, donor selection, structured cleanup strength, acceptance gates, rollback gates, or export reconstruction behavior.

## Root cause

`src/main.js` correctly attempts to calculate the preview footprint metric from:

```js
result.internalDetection.alphaMap
```

However, `src/video/worker.js` intentionally stripped the entire `internalDetection` object before posting the inspect result back to the main thread:

```js
const { internalDetection, ...publicResult } = result;
self.postMessage({ type: 'inspect-result', tag, result: publicResult });
```

Therefore the UI-side condition for `measureStructuredFootprintResidual(...)` was always false after the Web Worker boundary, and the formatter correctly rendered the absent values as `-`.

The v1.0.72 design documentation expected the main thread to receive the diagnostic alpha map, but the worker serialization path had not been updated to satisfy that contract.

## Fix

Added `src/video/inspectResultBridge.js` with `prepareInspectResultForWorker(result)`.

The bridge:

1. removes the full private/internal detection object from the worker result;
2. retains only `internalDetection.alphaMap`, which is the single internal field required by preview footprint measurement;
3. does not pass frame scores, private calibration internals, or other internal detection fields to the UI thread;
4. returns the previous public inspect payload unchanged when no alpha map is available.

`src/video/worker.js` now calls the bridge before posting `inspect-result`.

This keeps the existing `src/main.js` footprint computation unchanged while restoring the data dependency it already expected.

## Why the metric is not moved into pixel cleanup in this release

There is not yet enough real positive/control telemetry to set a safe footprint threshold. v1.0.74 only repairs observability so the same real samples can produce trustworthy values.

No `structured-footprint-suspect` risk flag, suppression pass, mask expansion, stronger shape-ghost pass, or rollback rule is introduced yet.

## Regression coverage

Added `tests/inspectResultBridge.test.mjs` covering:

1. the alpha map survives the worker bridge;
2. only `alphaMap` survives inside `internalDetection`;
3. `frameScores` and unrelated private/internal fields do not cross the worker boundary;
4. when no alpha map exists, `internalDetection` remains stripped as before.

The new bridge module is also included in `npm run check`.

## Safety statement

Expected pixel output is byte-for-byte unchanged because this release only changes inspect-result telemetry serialization. The export/process path still uses the full internal detection object inside the worker/engine and is not routed through the new inspect bridge.
