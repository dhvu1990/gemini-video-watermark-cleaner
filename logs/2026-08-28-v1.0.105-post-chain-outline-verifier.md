## Purpose

Address real-video evidence that v1.0.104 can leave a thin Gemini/Veo diamond/V contour after the main watermark body has already been cleaned, including cases where the broad final visual residual rescue reports an accepted result and therefore prevents the outline-only escalation pass from running.

This change remains limited to cleanup of the visible overlay in user-owned or authorized media. It does not target SynthID or other invisible provenance systems.

## Operator real-video evidence

The operator supplied six cleaned MP4 outputs from the current production behavior. The media itself is private test evidence and is not committed to this public repository.

Observed validation results:

- scene1-cleaned.mp4: body cleanup is strong, but a fixed diamond contour remains, especially along the right and lower edges. FAIL.
- scene2-cleaned.mp4: body mostly removed, but the lower V and right contour remain through multiple frames. FAIL/PARTIAL.
- scene3-cleaned.mp4: the full watermark contour remains readily recognizable on the blue background through the export even though the preview diagnostics had shown `Risk flags: none`. FAIL and verifier false-negative target.
- scene4-cleaned.mp4: watermark contour remains, but real crossing/linear scene structure is preserved. Cleanup FAIL/PARTIAL; scene-edge safety PASS. This remains the hard safety target.
- scene5-cleaned.mp4: best sample in the batch, but a faint lower V/ghost remains. PARTIAL.
- scene6-cleaned.mp4: strong stable diamond contour remains, including the right side and bottom point. FAIL.

Priority from the real-video batch: scene3 > scene6 > scene1 ~= scene2 > scene4 > scene5.

## Root cause found in v1.0.104

`applyStructuredSmoothRescue()` performed the broad/protected final visual residual rescue first. If that rescue returned `accepted=true`, the selected image was updated and the outline-only escalation stage was skipped entirely because v1.0.104 only called `applyOutlineResidualEscalation()` under `if (!finalAccepted)`.

This created a control-flow gap: an accepted broad residual improvement could still leave a low-alpha geometric outline that remained visually obvious, but the dedicated outline verifier never had a chance to inspect or correct it.

A second diagnostics gap existed in `src/batchPreviewModel.js`: accepted outline escalation modes were not mapped to user-facing labels, and batch risk flags only inspected `finalVisualResidual`, not the final post-chain outline state. As a result, a scene such as scene3 could display no risk flag while a recognizable diamond residual remained.

A test coverage gap was also identified in `tests/outlineResidualEscalation.test.mjs`: the original positive test used extremely permissive thresholds and only asserted improvement inside an `if (accepted)` block, so the test could still pass without proving that production-style gates accept an actual thin contour case.

## v1.0.105 implementation

### 1. Post-chain outline verification

`src/video/structuredSmoothRescue.js` now always runs the outline verifier against the currently selected image after the final visual residual stage, regardless of whether the broad final rescue was accepted or rejected.

The outline-only pass keeps all existing v1.0.104 safety gates:

- strong low-alpha geometric outline evidence,
- weak body residual requirement,
- multi-sector contour support,
- per-pixel scene-edge protection,
- whole-footprint crossing-scene-edge rejection,
- bounded blend/luma correction,
- global total/luma/chroma acceptance and rollback gates.

No detector threshold is lowered. No global alpha/body gain is increased. No broad ROI repainting is added.

### 2. Final post-chain outline metric

The selected output is measured again after the full rescue chain using the same outline geometry thresholds used by outline escalation. Diagnostics now include:

- `postChainOutlineResidual`
- `postChainOutlineResidual.strong`
- `postChainOutlineSceneSafe`

This separates the cleanup decision from the final visual warning state: a result may intentionally preserve a scene edge yet still report that an outline-like residual is present/protected.

### 3. Batch diagnostic parity

`src/batchPreviewModel.js` now recognizes outline-related accepted modes:

- `outline-residual-escalation`
- `structured-smooth+outline-escalation`
- `final-visual+outline-escalation`
- `structured-smooth+final-visual+outline-escalation`

It also surfaces:

- `outline-residual-escalation-rejected`
- `post-chain-outline-watermark-residual`
- `post-chain-outline-scene-protected`

The scene-protected flag is intentionally separate so scene4-style real structure is not treated as permission for more aggressive cleanup.

### 4. Bounded dense-but-quiet body gate correction

The first PR CI run exposed an additional production-gate problem in `residualBodyWeak()`.

`measureProtectedResidualField().candidateDensity` is effectively measurement/prediction coverage. On a smooth scene it can be close to 1.0 even when the measured body residual score is extremely low. v1.0.104 treated `candidateDensity > 0.38` as proof that the body was not weak, which could block outline-only escalation even when the body score itself was nearly clean.

The fix does **not** broadly raise `maxBodyDensity`. Instead, high coverage is tolerated only in a bounded `dense-but-quiet` case where the body residual score is at or below `0.50`. Stronger body residuals continue to fail the weak-body gate.

New diagnostics expose:

- `bodyScoreWeak`
- `bodyDensityWeak`
- `bodyQuietOverride`
- `lowBodyScoreOverride`
- `outlineDominance`
- `bodyDominanceSafe`

All outline-strength, sector-support, scene-edge, crossing-edge and global acceptance/rollback gates remain unchanged.

## Test changes

### `tests/outlineResidualEscalation.test.mjs`

Added a production-default positive case with a thin outer low-alpha diamond residual on a smooth background. The test requires:

- strong outline evidence,
- high measurement coverage to be recognized as `bodyDensityWeak=false`,
- the bounded quiet-body override to be the reason the body is still considered weak,
- scene safety,
- an actual outline escalation attempt,
- `accepted === true`,
- corrected pixels > 0,
- post-correction outline score lower than the pre-correction score.

Added a production-default negative case where a materially strong body residual must keep the outline-only escalation closed. The test requires `bodyQuietOverride=false`, `bodyWeak=false`, no attempt and no acceptance.

The existing crossing-line preservation regression remains in place.

### `tests/structuredSmoothRescue.test.mjs`

Added coverage proving that:

- an accepted final visual residual rescue still receives post-chain outline verification;
- post-chain outline diagnostics are always produced;
- a strong crossing scene line blocks the post-chain outline cleanup and is not materially altered.

### `tests/batchPreviewModel.test.mjs`

Added coverage for:

- outline accepted-mode labels;
- strong post-chain residual warning after an otherwise accepted final rescue;
- scene-protected outline warning without misclassifying it as safe-to-remove watermark residual.
