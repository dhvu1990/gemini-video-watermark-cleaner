# v1.0.33 - Codespaces runtime correction

Date: 2026-08-16

## Reason

The active application is being used through a private GitHub Codespace on Vite port `5173`, via a private `*.app.github.dev` forwarded URL. GitHub Pages is not the active runtime.

Earlier project documentation and the automatic Pages workflow still treated GitHub Pages as the primary deployment target, causing irrelevant failed deployment runs after merges to `main`.

## Changes

- Bumped project/runtime metadata to `v1.0.33`.
- Updated the visible app version to `v1.0.33`.
- Rewrote `CODESPACES.md` so private Codespaces port `5173` is the primary runtime.
- Rewrote `DEPLOYMENT.md` around the actual Codespaces workflow.
- Updated `README.md` to remove the stale GitHub Pages production-site claim.
- Removed `.github/workflows/deploy-pages.yml` so normal pushes to `main` no longer trigger an obsolete Pages deployment.
- Preserved the rule that the actual Codespaces `browseUrl` is dynamic and must not be hard-coded.

## Runtime architecture

```text
Private GitHub repository
-> GitHub Codespace
-> Vite on port 5173
-> private forwarded port
-> authenticated browser
-> local browser video processing
```

## Current user runtime

At the time this correction was made, the user was running the application through a private forwarded Codespaces URL on port `5173`. The concrete hostname is treated as session/runtime state rather than a permanent deployment URL because Codespaces hostnames can change when a Codespace is recreated.
