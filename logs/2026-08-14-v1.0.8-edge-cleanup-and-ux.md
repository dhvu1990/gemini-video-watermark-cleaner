# v1.0.8 - Edge cleanup, analysis feedback, and preview balance

Date: 2026-08-14
Project: Gemini Video Watermark Cleaner
Branch: `agent/v1.0.8`
Base: `main` at v1.0.7

## User regression evidence

The v1.0.7 real-browser test confirmed that detection and overlay alignment were fixed. The supplied portrait Gemini/Veo sample showed:

- automatic detector accepted the portrait inset candidate at roughly 88% match,
- the green bounding box aligned with the actual visible Gemini diamond,
- Original/Cleaned ROI previews were generated correctly,
- full video cleanup/export completed,
- the remaining quality defect was a clearly visible diamond outline after the bright interior had been removed.

The same test also exposed two UX issues:

1. analysis can take long enough that the user needs an unmistakable busy indicator,
2. the portrait full-frame preview is unnecessarily tall compared with the two ROI cards.

## Research

The current GargantuaX video implementation was re-inspected before changing cleanup behavior. Relevant upstream ideas include:

- the `96-20260520` video alpha profile,
- small video alpha edge boosts (around 0.035-0.045 for normal/inset geometry),
- optional alpha-shape evaluation with stronger edge-boost candidates,
- residual-cleanup backends including edge-band, footprint-polish, bilateral and temporal approaches,
- luma/gradient structure guards to avoid flattening genuine scene detail,
- optional Allenk/FDnCNN work for a higher-quality future tier.

Decision for v1.0.8: do not add the ML backend yet. Apply only lightweight browser-safe ideas that directly address the visible residual outline.

## Design constraints

The v1.0.7 detector result is already correct on the real portrait sample. Therefore:

- do not change catalog geometry,
- do not change coordinate refinement,
- do not make edge-boosted alpha the detector default,
- isolate quality changes to post-detection cleanup,
- preserve automatic full-scan fallback when a faster quick result is not sufficiently reliable.

## Implemented changes

### Faster progressive analysis

- quick sample count: 4 -> 3,
- quick scan window: first 25% -> first 18%,
- quick confidence floor: `max(0.22, minConfidence + 0.08)`,
- vote requirement: at least 2/3 when vote ratio is available,
- uncertain quick results continue automatically into the configured full scan.

This aims to reduce unnecessary early decoding while keeping fast acceptance stricter than normal detection.

### Busy feedback

- analysis button receives a `loading` state during quick/full detection,
- CSS draws a rotating spinner before the button label,
- status text and progress bar continue to update from Worker messages.

### Preview layout

- general full-frame preview column is bounded around 620 px,
- portrait preview column is bounded around 420 px,
- zoom cards remain 250 px on desktop,
- responsive layout stacks cleanly on narrow screens,
- source aspect-ratio mapping and v1.0.7 bounding-box alignment are preserved.

### Cleanup-only alpha edge enhancement

`enhanceAlphaEdges()` was added to the alpha module. It uses local alpha maxima and alpha gradients to strengthen weak low-alpha border pixels. The normal detector continues to use the unmodified map; edge enhancement is consumed by the post-detection cleanup path.

### Residual footprint cleanup

After normal inverse-alpha restoration and edge polish, the cleanup path now applies a bounded footprint pass:

- derives an edge/low-alpha band from the cleanup alpha map,
- expands evidence locally around weak watermark boundary pixels,
- samples a 7x7 neighborhood while preferring lower-alpha pixels,
- estimates local real-image structure using luma gradients,
- reduces cleanup weight on strong real edges,
- caps the blend so the ROI is not replaced by a generic blur patch.

The existing call to `applyEdgePolish()` is used both by detection preview and export, so the new residual pass automatically affects `ZOOMED CLEANED` and final video frames consistently.

## Tests added/updated

- progressive-analysis policy updated for 3 frames / 18% and stricter thresholds,
- alpha-edge tests verify weak border alpha is strengthened while remote empty background remains unchanged and values stay bounded,
- residual-cleanup test verifies a synthetic low-alpha edge band is modified while remote background remains untouched,
- existing inverse-alpha reconstruction regression remains in place.

## Known risk and review target

A synthetic test can verify bounded behavior but cannot prove visual quality on the real Gemini sample. The required post-deploy regression is therefore:

1. hard refresh production and confirm `v1.0.8`,
2. load the same `scene1.mp4`,
3. observe spinner and analysis responsiveness,
4. confirm auto-detected geometry remains at the same correct portrait inset location,
5. compare `ZOOMED CLEANED` against v1.0.7, specifically the four curved/diamond borders,
6. export the 6-second video and inspect several frames for residual outline, blur patching, flicker and scene-detail damage,
7. adjust residual strength/alpha shape only from that visual evidence.

## Future quality tier

If the residual diamond remains strong after v1.0.8, the next controlled experiment should be alpha-shape auto-selection (96 profile plus several edge-boost candidates scored by post-restoration residual confidence). Only after that should an optional ML/FDnCNN backend be considered.

## Release gate

Do not merge until GitHub Actions passes syntax checks, alpha synchronization, all unit tests and the Vite production build. After merge, require GitHub Pages build + deploy success before asking for the real-video regression test.
