# v1.0.63 — Evidence refinement with corrected ring-test isolation

Date: 2026-08-18

## Goal
Carry forward the evidence-gated structured-ring refinement from the failed v1.0.62 PR while correcting the unrelated legacy ring-isolation test that caused CI to fail.

## Why this version exists
v1.0.62 PR #63 failed CI run #672 because one older test assumed `acceptedMode` could only be `primary` or `micro-salvage`. The new evidence-refinement stage can validly append `evidence-refine`, so the old test was no longer isolated to its intended scope.

## Source behavior carried forward
The v1.0.62 evidence-refinement implementation is retained unchanged:
- refinement only runs when aligned residual score >= 1.75 and aligned sample density >= 0.012 by default;
- default refinement strength is 0.18, clamped to 0.08–0.30;
- the pass reuses the existing structured-ring repair logic;
- acceptance requires corrected pixels, at least 1.5% aligned-residual improvement, aligned score <= 98.5% of before, global total <= 100.2%, luma <= 100.4%, chroma <= 100.4%;
- unsafe candidates roll back completely.

## Correction
`tests/structuredRingSuppress.test.mjs` now sets `evidenceRefinement: false` in the shared `isolatedFinishers` fixture. This keeps primary/micro-salvage regression tests scoped to those stages only. Dedicated evidence-refinement tests remain responsible for validating the new stage.
