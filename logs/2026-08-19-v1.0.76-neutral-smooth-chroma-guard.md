# v1.0.76 — Neutral Smooth Chroma Guard

Date: 2026-08-19

## Objective

Reduce color contamination introduced by smooth-background reconstruction on near-neutral white/gray backgrounds without increasing cleanup strength globally and without changing the structured-background pipeline.

## Benchmark trigger

The fixed six-sample benchmark now used for visual validation exposed two separate failure classes:

- B1: structured dark residual / center-seam footprint;
- B5: smooth near-neutral background where the cleaned preview developed a visible yellow/green/cyan cast inside the reconstructed watermark footprint;
- B2/B3/B4/B6: control samples that are currently acceptable and must not regress.

This release addresses only B5. B1 is intentionally deferred until the v1.0.75 structured-footprint telemetry from the fixed benchmark is available.

## Root-cause hypothesis

`applySmoothBackgroundReconstruction(...)` fits independent quadratic RGB surfaces from clean exterior pixels and then replaces most of the watermark footprint with the fitted RGB prediction.

On a near-neutral background, small independent R/G/B fitting errors can become a visible chroma cast even when luma and global smoothness are reasonable. Because the previous implementation reconstructed all RGB channels directly, there was no explicit constraint tying predicted chroma back to the clean neutral exterior color.

The failure can therefore appear as a faint colored diamond even though the background itself is almost white or gray.

## Change

`src/video/smoothBackground.js` now measures clean-exterior chroma statistics while fitting the background surface:

- exterior mean Cb;
- exterior mean Cr;
- exterior chroma magnitude;
- exterior chroma spread;
- derived `neutralChromaConfidence`.

The confidence is high only when both:

1. the clean exterior mean is close to neutral;
2. exterior chroma variation is small.

During smooth reconstruction, when neutral confidence is high, the predicted surface keeps its fitted luma but its Cb/Cr values are softly pulled toward the measured clean exterior mean. The correction is spatially weighted by the existing feather/body mask.

The guard does not force exact gray. A real slight tint in the exterior reference is preserved because the target is the measured exterior mean Cb/Cr, not zero chroma.

## Safety behavior

- Enabled only inside the existing `smooth-rebuild` path.
- Does not alter structured-background logic, structured ring suppression, center seam, local tone, outer halo, temporal donor, atlas, or calibration.
- Saturated smooth backgrounds receive near-zero neutral confidence and therefore do not activate the guard.
- Existing smooth-mode safety gates remain unchanged.
- Luma reconstruction is unchanged by the neutral chroma guard.
- Default guard strength is bounded to 0.78 with a hard option cap of 0.90.
- Guard contribution is feather/body weighted rather than applied to the entire ROI.

## Diagnostics added

Smooth-background result metadata now includes:

- `exteriorChromaMagnitude`
- `exteriorChromaSpread`
- `neutralChromaConfidence`
- `neutralChromaGuardApplied`
- `neutralChromaGuardPixels`
- `meanChromaCorrection`

These fields are currently carried in runtime diagnostics; no UI threshold or automatic risk flag is added in this release.

## Regression coverage

`tests/smoothBackground.test.mjs` now covers:

1. the existing smooth gradient reconstruction remains strongly effective;
2. a synthetic near-neutral background with deliberately biased fitted RGB coefficients receives a chroma correction and shows substantially lower chroma contamination with the guard enabled;
3. a saturated cyan smooth background receives low neutral confidence and does not activate the guard;
4. the existing structured keyboard-like control remains rejected from aggressive smooth reconstruction.

## Explicit non-goals

This release does not attempt to solve the B1 structured dark seam/footprint by raising any global strength. That work remains gated by real v1.0.75 footprint class/evidence telemetry from the fixed benchmark.

## Required CI gates

Before merge:

1. dependency install
2. sync pinned alpha profiles
3. `npm run check`
4. `npm test`
5. `npm run build`

Do not merge if any required gate fails.

## Post-merge visual validation

Re-run the fixed B1–B6 benchmark.

Primary success criterion:

- B5 should lose the visible yellow/green/cyan footprint or show a clear reduction.

Non-regression criteria:

- B2/B3/B4/B6 must remain at least as clean as v1.0.75;
- B1 may remain unchanged in v1.0.76 because the structured path is intentionally untouched.

For the next structured-focused release, record B1/B2/B3/B4/B6 footprint score, raw score, coverage, shape-aligned density, continuity discount, class, evidence, and class reason.
