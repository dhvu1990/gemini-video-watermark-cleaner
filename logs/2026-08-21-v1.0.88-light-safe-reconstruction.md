# v1.0.88 — Light-Safe Reconstruction and Scene-Edge Consensus Protection

Date: 2026-08-21

## Trigger

Two new seven-scene real-video batches were reviewed after v1.0.87.

The dark/structured batch showed that the v1.0.87 adaptive alpha underflow cap materially improved the catastrophic scene5 black-diamond collapse, but scene5 still needs another visual check for a remaining dark local tone patch.

The second, mostly light/beige batch exposed the next two failure classes:

1. scene3 produced a clearly wrong brown/yellow reconstruction patch near a strong real scene boundary;
2. scene1/2/4/7 retained faint Gemini/Veo shape ghosts on light backgrounds even though aggressive global cleanup would be unsafe.

The release strategy is therefore safety-first: do not increase global structured strength. Protect real scene boundaries first, then open a narrow light-background micro-cleanup path for faint residuals.

## Change 1 — structured consensus scene-edge protection

`src/video/structuredConsensusRepair.js`

The directional consensus stage previously used local gradient/anchor disagreement guards, but it did not reuse the dedicated v1.0.84 scene-edge protection model. A high-contrast scene boundary could therefore still supply incompatible directional anchors and create an incorrect local color reconstruction even while the global residual metric improved.

v1.0.88 now:

- evaluates `sceneEdgeProtectionAt()` for every structured-consensus candidate pixel;
- hard-skips pixels with strong real-scene-edge evidence;
- continuously attenuates remaining consensus blend as scene-edge evidence rises;
- measures whole-footprint `measureCrossingSceneEdgeRisk()` before candidate acceptance;
- requires stronger residual improvement when a crossing edge is protected;
- tightens the allowed chroma regression from 0.8% to 0.2% on protected crossing-edge scenes;
- exposes `crossingEdge`, `sceneGuardedPixels`, `meanSceneProtection`, `candidateImprovement`, and `requiredImprovement` diagnostics.

This specifically targets the light-batch scene3 wrong-color patch without reducing cleanup globally on normal structured scenes.

## Change 2 — conservative light-background micro ghost cleanup

`src/video/shapeGhostSuppress.js`

The existing micro-ghost path was primarily opened by smooth-background confidence and had additional dark-scene emphasis. The new light batch showed faint residual geometry on bright beige/white surfaces that can remain below the normal shape-ghost threshold.

v1.0.88 adds:

- mean footprint luma telemetry;
- a bounded `lightConfidence` signal combining bright-surface evidence with smooth/textured anchor support;
- a new light micro eligibility gate that can open below the normal full shape-ghost score threshold;
- a small light-only micro boost for coherent residuals;
- reduced chroma blending on bright pixels so cleanup remains primarily luma-driven;
- reduced texture reconstruction strength when the light micro path is active;
- a stricter light-path chroma acceptance envelope;
- `lightMicroEligible`, `lightMicroPixels`, and `microStrength` diagnostics.

No global structured-ring, protected-rescue, alpha, local-tone, or empty-zone strength was increased.

## Regression coverage

Updated tests cover:

1. structured consensus guarding a high-contrast real boundary crossing the watermark footprint;
2. light smooth surfaces entering the conservative micro-ghost path;
3. light-path chroma safety;
4. existing disabled/high-detail/normal shape-ghost behavior remains covered.

1. **Light batch scene3** — release blocker: the brown/yellow reconstruction patch must disappear and the beige/purple real boundary must remain intact.

3. **Light batch scene1/2/4/7** — look for a measurable reduction in faint Gemini/Veo ghost geometry without new color/tone patches.
4. Preserve currently good scenes: dark batch scene1/3/4/6/7 and light batch scene6.
