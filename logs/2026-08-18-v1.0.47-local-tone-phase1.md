## Status

Phase 1 implemented as a standalone guarded module. It is intentionally not wired into the runtime cleanup stack yet. Runtime integration will only happen after CI validates the isolated behavior.

## Motivation

The cleaned-preview comparisons showed cases where the watermark silhouette was mostly removed but the repaired footprint still had a local brightness mismatch against the surrounding background. This was especially visible on smooth orange, navy and cyan backgrounds. A global blur or stronger generic ring cleanup would risk damaging structured scenes, so this phase targets only low-gradient local tone mismatch.

## Added module

`src/video/localToneMatch.js`

Core approach:
- derive the watermark footprint from the alpha map;
- collect only low-alpha, low-gradient reference pixels just outside the footprint;
- fit a robust local luma plane to those clean reference pixels;
- measure the signed median luma mismatch inside the eligible watermark footprint;
- apply a bounded luma-only shift to low-gradient pixels that agree with the measured mismatch;
- never blur or average scene detail;
- run a try-measure-accept gate and restore the exact input if the candidate is not safer.

## Safety gates

Default protection includes:
- reference alpha <= 0.012;
- reference gradient guard;
- target alpha band roughly 0.07-0.68;
- target gradient guard;
- minimum reference and target sample counts;
- minimum mismatch score before attempting;
- maximum luma shift of 10;
- required local tone mismatch improvement;
- global `measurePostCleanupResidual` gates for total, luma and chroma;
- exact input restoration when rejected.

Phase 1 is luma-only. Conservative chroma matching is intentionally deferred because color correction has a higher risk of tinting textured or structured backgrounds.

## Tests

Added `tests/localToneMatch.test.mjs`:

2. high-detail checkerboard should not be accepted and must remain byte-identical;
