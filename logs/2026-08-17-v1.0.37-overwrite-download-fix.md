# v1.0.37 - Overwrite-safe download release

Date: 2026-08-17

## Problem

After cleaning a video, Chrome/Windows could fail the download when the user selected the original source file as the overwrite target. The page still had the original selected video attached to the preview `<video>` through a blob URL at the moment the browser opened the save/overwrite operation.

## Change

- Added `src/downloadGuard.js`.
- Immediately before the download anchor performs its default browser download action, the guard pauses the original preview, removes its `src`, reloads the media element, revokes the original source blob URL, and clears the file input value.
- The cleaned result blob URL and result preview remain untouched, so the generated MP4 remains downloadable/reviewable.
- Added regression tests for source release and the no-source case.
- Bumped package, worker metadata and visible UI version to v1.0.37.

## Expected behavior

The user may click **Download cleaned MP4**, choose the original input file as the destination, confirm overwrite, and the browser should no longer be blocked by the page still consuming the source preview.

## Notes

This change only affects download/source-resource lifecycle. Cleanup algorithms remain the v1.0.36 pipeline.
