# v1.0.17 — Subpixel Alpha Registration + Residual Buckets

Date: 2026-08-14

## Context

Real-video validation of v1.0.16 showed a large quality improvement: the restored core retained scene texture and the normal-direction edge bridge reduced the visible Gemini diamond outline. The remaining artifact is now mostly a thin anti-aliased edge rather than a large incorrect footprint.

This indicates that integer-pixel detector geometry is already correct, while the embedded alpha profile can still be fractionally misregistered relative to the actual encoded overlay. A 0.2–0.4 px alpha mismatch is enough to leave a visible outline after inverse-alpha restoration.

## Upstream research

The current GargantuaX/gemini-watermark-remover v1.0.40 research tooling fits video alpha profiles using small shape scales and subpixel offsets, including approximately ±0.4 px offsets, and separately studies alpha/gradient residual regions. This release adapts those ideas to the browser-local pipeline without importing the upstream implementation wholesale.

## Design

### Two-stage bounded calibration

The existing bounded coarse search remains responsible for selecting:

- embedded alpha profile (`96-20260520` / `96`),
- shape scale,
- edge boost,
- edge gain.

The shape-scale candidates are tightened to `0.985 / 1.000 / 1.015` because v1.0.16 is already close enough that large footprint changes are no longer desirable.

After the coarse winner is known, a second pass evaluates only nine subpixel registrations:

- X offset: `-0.4 / 0 / +0.4 px`,
- Y offset: `-0.4 / 0 / +0.4 px`.

This keeps the search bounded (~63 candidates instead of multiplying the full coarse grid by nine) so the analysis remains practical in the Web Worker.

### Bilinear alpha registration

`transformAlphaRegistration()` samples the alpha map bilinearly while applying scale and fractional X/Y offsets. The source video pixels and detector bounding box remain unchanged.

### Residual buckets

The calibration objective is now split into diagnostic regions:

- `nearZero`: pixels effectively outside the watermark footprint,
- `edge`: alpha-gradient/anti-aliased edge pixels,
- `lowBody`: lower-alpha interior pixels,
- `highBody`: high-alpha core pixels.

The combined score weights the edge bucket most strongly while still penalizing damage to low/high body and outside pixels. This lets calibration improve a thin outline without flattening the core texture restored by v1.0.15/v1.0.16.

## UI diagnostics

The Tune panel now exposes:

- selected profile,
- shape scale,
- subpixel Offset X / Offset Y,
- edge gain,
- edge boost,
- total residual,
- edge residual,
- low-body residual,
- high-body residual.

The expected interpretation is that, once body residuals are already low, a high edge residual should drive subpixel/edge fitting instead of stronger whole-footprint cleanup.

## Pipeline compatibility

The calibrated alpha map is still stored in the active Web Worker and reused by detection preview and export. The v1.0.16 cleanup stack remains intact:

1. calibrated inverse-alpha restoration,
2. detail-preserving hybrid core/ring repair,
3. padded texture repair,
4. optional temporal/multi-frame atlas,
5. normal-direction edge bridge,
6. temporal stabilization.

Detector/catalog integer geometry is unchanged.

## Regression gates

Added/updated tests require:

- fractional alpha registration to move the alpha center of mass in the requested direction,
- alpha-map dimensions to remain unchanged,
- residual buckets to isolate edge damage from high-body damage,
- all existing body-gain, core-preservation, edge-bridge, temporal and export regressions to remain green.
