# v1.0.66 — Temporal donor acceptance runtime integration

Date: 2026-08-18

## Goal
Integrate the v1.0.65 temporal-donor acceptance gate into the real repair runtime so a single-frame temporal donor candidate can be rolled back before downstream edge/ring finishing when residual safety metrics worsen.

## Why this step
v1.0.64 added a local-structure guard inside temporal donor blending. v1.0.65 then added standalone pass-level acceptance infrastructure. Until this version, the engine still accepted any temporal donor candidate that passed the local donor logic. The remaining safety gap was the absence of whole-pass try/measure/accept/rollback at the existing temporal fallback call site.

## Runtime logic
The atlas flow is unchanged.

When history exists:
1. build the temporal atlas as before;
2. if atlas donor/support thresholds pass, use the atlas as before and do not attempt single-frame donor fallback;
3. if atlas is insufficient and masked donors are not allowed, keep the pre-donor repaired image as `baseline`;
4. create the temporal donor `candidate` with the existing strength 0.52 and existing local-structure guard;
5. run `evaluateTemporalDonorAcceptance(baseline, candidate, paddedAlpha)`;
6. use the candidate only when the acceptance helper passes its total/luma/chroma residual safety gates;
7. otherwise restore the exact baseline before running normal edge bridge and dual-ring finish.

## Diagnostics
`repairPaddedRegion()` now exposes `temporalDonorAcceptance` containing:
- attempted / accepted / reason;
- baseline and candidate residual metrics when measured;
- total/luma/chroma ratios and improvement;
- temporal shift diagnostics;
- temporal donor local-structure diagnostics.

Detection preview forwards the same diagnostic block.

Video export metadata adds:
- `temporalDonorAcceptance: true`
- `temporalDonorAttemptedFrames`
- `temporalDonorAcceptedFrames`
- `temporalDonorRejectedFrames`

## Safety boundaries
- No atlas threshold change.
- No atlas blend-strength change.
- No temporal donor strength change (still 0.52 at this call site).
- No local-structure thresholds changed.
- No alpha calibration changes.
- No structured cleanup or ring thresholds changed.
- The new gate can only keep the candidate or roll back to the baseline; it cannot increase cleanup strength.

## Tests
Added runtime integration coverage for:
1. empty history reports no temporal donor attempt;
2. insufficient atlas support exposes temporal-donor acceptance diagnostics through the real `repairPaddedRegion()` call path.

The detailed acceptance/rollback decision bounds remain covered by `tests/temporalDonorAcceptance.test.mjs` from v1.0.65.
