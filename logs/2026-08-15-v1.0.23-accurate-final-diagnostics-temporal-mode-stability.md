# v1.0.23 — Accurate Final Diagnostics + Temporal Mode Stability

Date: 2026-08-15

## Motivation

Real-video validation of v1.0.22 showed that adaptive background classification works correctly:

- the textured keyboard sample was classified as `structured`,
- the smooth USB-C sample was classified as `smooth-rebuild`,
- the USB-C watermark became visually almost invisible after full-footprint reconstruction.

Two follow-up issues remained:

1. The Post-clean diagnostics card still showed pre-rebuild residual values, so the numbers did not match the visibly cleaner `ZOOMED CLEANED` preview.
2. Per-frame background classification could theoretically oscillate between `smooth-rebuild` and `structured` near thresholds, which could cause temporal flicker in exported video.

## Goals

- Measure final residual only after every adaptive finishing step has completed.
- Keep preview diagnostics aligned with the exact image shown in `ZOOMED CLEANED`.
- Add temporal hysteresis so background mode does not flap frame-to-frame.
- Preserve immediate safety fallback when a clearly structured/object-rich frame appears.
- Reset temporal state at the beginning of each inspect/process worker task.

## Implementation

### Accurate final diagnostics

`applyDualRingLumaFinish()` now computes:

- `finalCleanup.before` immediately before optional smooth reconstruction,
- `finalCleanup.after` after the final selected output,
- `finalCleanup.improvement`,
- `finalCleanup.source` (`post-smooth-rebuild` or `post-structured-finish`).

`src/main.js` now prefers `preview.dualRingFinish.finalCleanup` instead of the older edge-bridge diagnostic snapshot.

This makes Final total / luma / chroma residual correspond to the actual cleaned preview.

### Temporal mode stability

New module:

`src/video/adaptiveFinish.js`

The module keeps a small mode state inside the Web Worker:

- the first frame selects its raw classifier mode immediately,
- `structured -> smooth-rebuild` requires 2 consecutive smooth decisions,
- a borderline `smooth-rebuild -> structured` change requires 2 consecutive structured decisions,
- a strongly unsafe structured frame exits smooth mode immediately,
- mode switch / hold counters are exposed in diagnostics.

`resetAdaptiveFinishState()` is called at the beginning of each inspect and process request so one video/task cannot leak its mode into another.

### Safety behavior

A hard unsafe frame is detected when one or more structure metrics substantially exceed their normal safety limits. This bypasses hysteresis and switches to `structured` immediately so an object or strong edge entering the watermark footprint is not blurred/rebuilt aggressively.

## Regression coverage

Added `tests/adaptiveFinish.test.mjs`:

1. One borderline structured frame must not immediately flip a smooth sequence.
2. A second consecutive borderline structured frame confirms the switch.
3. A hard unsafe frame must switch to structured immediately.
4. Smooth rebuild must report diagnostics from the post-reconstruction output.

Existing smooth-background and structured-background regression tests remain active.
