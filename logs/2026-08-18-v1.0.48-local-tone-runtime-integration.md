# v1.0.48 - Local Tone Match runtime integration

Date: 2026-08-18

## Baseline
- PR #48 / v1.0.47 passed CI run #541.
- v1.0.47 was squash-merged to `main` as `491f565a7c04398a66fe35975808da9578ac557e`.
- Local Tone Match existed as a standalone guarded module and was intentionally not wired into runtime in Phase 1.

## Goal
Wire Local Tone Match into the structured cleanup chain only, after Center Seam, without changing the smooth-background reconstruction branch or globally increasing repair strength.

## Runtime order
1. Structured consensus
2. Structured ring
3. Micro-salvage when eligible
4. Shape ghost suppression
5. Center seam suppression
6. Local tone match

## Implementation
Updated `src/video/structuredRingSuppress.js`:
- imports `applyLocalToneMatch` from `localToneMatch.js`;
- adds `finishWithLocalTone(...)` with explicit `localToneMatch: false` opt-out;
- runs Local Tone Match after Center Seam in both the low-residual skip branch and the primary/salvage branch;
- only replaces the selected image when the standalone Local Tone Match safety gates accept the candidate;
- exposes diagnostics as `structuredRing.localToneMatch`;
- appends `+local-tone` to `acceptedMode` only when accepted;
- includes Local Tone Match acceptance in the structured-stage overall accepted flag.

## Safety boundaries retained
- Local Tone Match remains luma-only.
- No chroma correction added.
- No outer-halo expansion added.
- No smooth-rebuild changes.
- No global strength increase.
- Local Tone Match keeps its standalone robust plane fit, low-gradient guard, bounded shift, global residual gates, and exact rollback on rejection.

## Tests
Added `tests/localToneRuntimeIntegration.test.mjs`:
- verifies structured runtime exposes Local Tone Match diagnostics after the Center Seam stage;
- verifies `acceptedMode` only contains `local-tone` when the candidate is actually accepted;
- verifies explicit `localToneMatch: false` opt-out stays disabled and never changes mode.
