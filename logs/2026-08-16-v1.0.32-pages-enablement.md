# v1.0.32 — GitHub Pages Auto-Enable

Date: 2026-08-16

## Motivation

v1.0.31 passed CI and merged successfully, but the post-merge GitHub Pages workflow failed at `actions/configure-pages@v6` because the repository did not yet have a Pages site enabled/configured for GitHub Actions.

All application validation steps in that failed deployment run were successful:

- dependency install: PASS,
- pinned alpha profile sync: PASS,
- syntax checks: PASS,
- 70/70 unit/regression tests: PASS,
- Vite production build: PASS.

The failure was deployment configuration only, not application code.

## Change

`.github/workflows/deploy-pages.yml` now calls:

```yaml
- name: Configure GitHub Pages
  uses: actions/configure-pages@v6
  with:
    enablement: true
```

This allows the workflow to request Pages enablement/configuration when the Pages site does not yet exist, instead of failing immediately on the site lookup.

## Version

Because this project increments the version on every edit, package metadata, worker export metadata, and visible UI version were advanced to `1.0.32`.

## Release gate

Merge only after CI passes on the exact PR head. After merge, verify that the GitHub Pages workflow completes successfully.
