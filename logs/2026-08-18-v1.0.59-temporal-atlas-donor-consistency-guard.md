# v1.0.59 — Temporal atlas donor-consistency guard

Date: 2026-08-18

## Goal
Reduce structured-background streak/paint artifacts caused when temporally aligned donor frames disagree strongly at the same reconstructed pixel.

## Cause
`buildBackgroundAtlas()` previously used per-channel medians and donor-count/alignment improvement to derive confidence, but did not reduce confidence when aligned donors still had large local luminance disagreement. A globally acceptable shift can still be locally wrong on structured or moving content; the atlas could therefore blend a locally inconsistent median into the watermark edge/feather region.

## Algorithm / logic
- Compute per-pixel donor luminance values after the existing shift and donor-validity checks.
- Measure robust donor spread using median absolute deviation (MAD) around the donor luminance median.
- Convert spread to a smooth consistency factor with conservative defaults:
  - soft threshold: 10 luma units
  - hard threshold: 32 luma units
- Multiply the existing atlas confidence by this consistency factor.
- Keep the existing median RGB reconstruction, donor support thresholds, hybrid region mask, and final blend caps unchanged.
- Expose `donorSpread`, `meanDonorSpread`, `donorSpreadSoft`, and `donorSpreadHard` for diagnostics.

## Why this is bounded
This change only lowers confidence for locally inconsistent temporal donors. It does not increase any repair strength, expand the watermark mask, alter calibration, or introduce a second reconstruction system.

## Tests
Added a regression case that builds one coherent donor set and one brightness-divergent donor set. The inconsistent set must report materially larger donor spread and lower mean atlas confidence while retaining the configured soft/hard thresholds in diagnostics.

Existing tests continue to cover:
- shift estimation
- clean-pixel donor acceptance
- masked cleaned-donor reconstruction
- edge-ring vs high-alpha-core blend behavior
