# v1.0.86 - Dark inverse-alpha underflow guard

Date: 2026-08-20
Branch: `agent/v1.0.86`
Base: `main` at v1.0.85
Primary visual blocker: scene5 dark-background black-hole failure.

## Problem confirmed from real preview

The latest seven-scene preview showed scene5 collapsing into a near-black diamond-shaped patch. This failure was already visible before the new protected residual rescue stage and therefore must not be treated as a residual-rescue tuning problem.

The failure mechanism is consistent with inverse-alpha over-correction on a dark background. The existing white-overlay inverse is:

`background = (source - alpha * 255) / (1 - alpha)`

When detected alpha/gain is slightly too high, a dark true background can produce a negative reconstructed value. Byte clamping then turns that value into 0, creating a black footprint aligned with the watermark body.

## Design decision

Do not weaken the v1.0.84/v1.0.85 scene-preservation guards and do not increase global structured cleanup strength.

Instead, add a bounded correction immediately after inverse-alpha reconstruction and before edge polishing.

## New module

`src/video/darkUnderflowGuard.js`

### Detection

The module measures suspicious collapse only when all of the following are true:

- alpha is in a meaningful watermark-body range;
- inverse-restored luma is near black;
- the original composite pixel is substantially brighter than the collapsed reconstruction;
- at least two two-sided clean-anchor directions are available;
- clean-anchor predictions agree within bounded spread/disagreement thresholds;
- predicted clean background is meaningfully brighter than the collapsed reconstruction.

This prevents a genuine near-black background from being lifted merely because it is dark.

### Background estimate

Four possible two-sided clean-anchor directions are evaluated:

- horizontal;
- vertical;
- diagonal down-right/up-left;
- diagonal up-right/down-left.

Each valid direction interpolates between clean pixels outside the alpha footprint. The final target is the median consensus across directions, reducing sensitivity to a single bad donor.

### Scene-detail protection

The guard reuses `sceneEdgeProtectionAt()` from v1.0.84. Strong real scene edges can therefore block correction locally rather than allowing the underflow guard to paint across true boundaries.

### Candidate correction

Correction is limited by:

- predicted clean-anchor confidence;
- amount of black collapse;
- alpha/body confidence;
- real-scene-edge protection;
- a bounded maximum blend.

The module does not repaint the complete watermark footprint and does not use broad blur.

### Acceptance

The complete candidate is rolled back unless it removes a substantial fraction of measured underflow pixels and reduces mean collapse. This keeps the stage try/measure/accept rather than unconditional.

## Runtime integration

`inverseAlphaRestore()` now:

1. performs the original mathematical inverse-alpha reconstruction;
2. calls `applyDarkUnderflowGuard(restored, originalComposite, alphaMap)`;
3. returns the accepted guarded result, if any;
4. preserves a `darkUnderflowGuard` diagnostic object on the immediate inverse result.

The existing later pipeline remains unchanged:

`inverse alpha -> dark underflow guard -> edge polish -> padded texture repair -> temporal repair -> edge bridge -> dual-ring/structured finishing`

## Regression tests

Added `tests/darkUnderflowGuard.test.mjs` covering:

1. synthetic dark background + white watermark + intentionally over-gained inverse causing black collapse; guard must recover toward the clean dark background;
2. direct `inverseAlphaRestore()` integration; guard must run automatically;
3. genuine near-black clean background; guard must stay inactive and preserve exact pixels;
4. strong real light/dark boundary through the footprint; output must retain meaningful side-to-side contrast.
