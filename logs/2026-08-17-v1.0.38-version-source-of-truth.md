# v1.0.38 - Runtime version source of truth

## Problem

The deployed page could show an old `v1.0.30` badge even though the HTML, worker and package had already advanced to newer releases. The cause was `src/calibration-ui.js`, which still contained a hard-coded `APP_VERSION = '1.0.30'` and rewrote the visible badge/title at runtime.

A regression test also explicitly expected the stale `1.0.30` value, so CI did not catch the mismatch.

## Fix

- Added `src/version.js` as the shared runtime version source.
- `src/calibration-ui.js` imports the shared version instead of hard-coding a value.
- `src/video/worker.js` imports the same shared version for exported metadata.
- Updated the version regression test to verify both UI and worker use the shared source.
- Bumped package/runtime version to `1.0.38`.

## Result

The visible badge, page title and exported worker metadata can no longer silently drift because of separate hard-coded runtime constants.
