# v1.0.16 - Normal-Direction Edge Bridge

Date: 2026-08-14

## Trigger

Real-video testing of v1.0.15 showed that the hybrid core/ring split was the right direction: internal texture became visibly sharper again compared with v1.0.14, while the remaining defect was concentrated around the Gemini diamond outline.

The user explicitly confirmed that the current result is better and asked to focus only on improving the visible edge.

## Goal

Keep the v1.0.15 core almost unchanged while improving only the residual diamond edge/halo.

Target visual behavior:

- preserve the detailed texture inside the watermark footprint;
- avoid whole-ROI atlas blur;
- repair only the 1-4 px edge ring and feather transition;
- avoid destroying real background structures that cross the watermark;
- use the same final edge repair for preview and full-video export.

## Root cause being addressed

Earlier cleanup strategies could suppress the visible white overlay but still leave a dark/blue diamond outline. Increasing Body gain, Edge gain, Edge polish, or atlas blending further would risk flattening the internal texture that v1.0.15 successfully restored.

The residual is now primarily a boundary continuity problem rather than a whole-footprint reconstruction problem.

## v1.0.16 design

### Normal-direction edge bridge

Added `src/video/edgeBridge.js`.

For each pixel in the hybrid edge ring:

1. compute the local alpha gradient;
2. treat the normalized alpha gradient as the approximate inward/outward normal of the watermark boundary;
3. search outward along the negative normal for a clean low-alpha background anchor;
4. search inward along the positive normal for a stronger-alpha/core anchor that has already been restored by inverse-alpha/hybrid processing;
5. interpolate between the two anchors to predict the missing boundary transition;
6. blend only inside the edge ring/feather region.

The high-alpha core is heavily protected and excluded when its core mask becomes dominant.

### Structure guard

If the inner and outer anchors differ strongly in RGB, that is treated as evidence that a real scene edge crosses the watermark region. In that case the edge-bridge blend is reduced substantially.

The correction delta is also clamped so the bridge cannot create a large false color jump.

### Pipeline position

The bridge runs after:

- inverse-alpha restoration;
- edge polish;
- hybrid padded spatial repair;
- optional atlas/temporal repair.

It runs before the final temporal correction stabilization used by export.

Therefore it is a narrow final residual-edge pass rather than another whole-ROI reconstruction layer.

## Diagnostics

The edge bridge returns:

- `bridgedPixels`;
- `meanBlend`.

Export metadata records:

- `normalEdgeBridge: true`;
- `bridgeFrames`;
- `bridgePixelsPeak`.

These values make it possible to determine whether the pass is actually activating on real videos.

## Regression tests

Added `tests/edgeBridge.test.mjs` with two critical cases:

1. a synthetic dark diamond ring must move closer to the clean background while high-alpha core detail remains essentially unchanged;
2. a strong real brightness edge crossing the ROI must trigger the structure guard and remain largely preserved.

The package syntax check now includes `src/video/edgeBridge.js`.
