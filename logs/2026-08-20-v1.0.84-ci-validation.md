### Root cause

The synthetic test sampled the *center of a 2–3 px wide dark diagonal stripe*. Central-difference gradient at the stripe center is correctly near zero because both immediate neighbors are also inside the same flat dark stripe.

The ROI-level crossing-edge tests already passed and proved the detector was finding the stripe boundaries. The failure was therefore a bad unit-test sampling assumption, not a detector implementation failure.

### Fix

Commit: `b5f91996326326301fef329e74412cec0472cce8`

The per-pixel regression test was changed to scan a small neighborhood around the synthetic diagonal stripe and compare:

- the strongest detected stripe-boundary protection sample;
- a nearby smooth sample.

The test now checks the actual intended behavior: **boundary pixels of a genuine scene edge receive stronger protection than smooth surrounding pixels**.

No runtime threshold or production detector logic was weakened to make the test pass.
