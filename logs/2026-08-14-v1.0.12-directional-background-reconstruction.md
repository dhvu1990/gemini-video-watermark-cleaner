# v1.0.12 — Directional Background Reconstruction

Date: 2026-08-14

## Trigger / real-video observation

Regression testing on the same 1080x1920 Gemini/Veo sample showed that v1.0.11 fixed the center over-correction from v1.0.10:

- detection remained stable around 88% confidence;
- detector geometry remained x=864, y=1704, size=72;
- estimated alpha gain was about 1.125;
- calibrated Body gain dropped to about 0.990;
- the selected profile became `96-20260520`;
- shape scale stayed at `1.000`;
- Edge gain reached the search maximum `1.30`;
- Edge boost remained `0.030`;
- residual score was about `13.597`.

The cleaned ROI no longer had the strongly darkened center seen in v1.0.10, but the diamond outline was still clearly visible. Because Edge gain had already reached the upper search bound, continuing to increase alpha correction or blur was no longer the preferred next step.

## Research direction

The current upstream `GargantuaX/gemini-watermark-remover` video cleanup work includes weighted cleanup masks, structure guards, inpainting/texture repair paths, edge-band cleanup and optional denoise backends. This supported moving the local browser implementation from additional alpha correction toward explicit background reconstruction for the remaining residual edge.

## Final implementation

Added `applyDirectionalEdgeReconstruction()` to `src/video/restore.js`.

The final algorithm is intentionally limited to the residual edge band:

1. Compute the gradient of the calibrated alpha map.
2. Use the alpha gradient as the local normal direction to the watermark outline.
3. Search along both normal directions for low-alpha background anchors.
4. A single valid outward anchor is sufficient. This is important for a closed watermark shape because the opposite normal direction often points through the watermark body rather than directly into background.
5. If both anchors are available, interpolate between them. If only one is available, use that background sample with reduced support/blend strength.
6. Bilinearly sample RGB values from the anchor position(s).
7. Reduce reconstruction strength when two anchors disagree strongly, which indicates a real image boundary may cross the watermark region.
8. Use the maximum luma gradient in a 3x3 neighborhood as a structure guard. This protects thin real lines that can have a near-zero symmetric derivative exactly at their center pixel.
9. Limit the repair to low/mid-alpha residual edge pixels and avoid the watermark body/core.

## Pipeline placement

Directional reconstruction is applied after:

- inverse-alpha restoration;
- calibrated body/edge gain;
- local edge polish;
- residual footprint cleanup.

Because `applyEdgePolish()` is shared by both the sampled `ZOOMED CLEANED` preview and the full-video export path, the directional reconstruction is automatically applied consistently to both preview and exported MP4.

## Safety / quality constraints

- no global blur;
- no ML model dependency;
- no reconstruction in high-alpha center pixels;
- at least one valid low-alpha background anchor is required;
- one-sided anchors use reduced blend support;
- strong cross-anchor color differences reduce blend strength when two anchors exist;
- strong image structure in the surrounding 3x3 neighborhood strongly reduces blend strength;
- the repair remains bounded to the calibrated watermark ROI.

## Tests

Extended `tests/restore.test.mjs` with two directional-repair regression cases:

1. **Smooth-background halo repair** — creates a known smooth RGB background, injects a dark residual into the low-alpha watermark edge band, applies directional reconstruction, and requires mean RGB error to move closer to the known original.
2. **Strong-structure preservation** — adds a thin bright line crossing the ROI and verifies directional reconstruction does not materially erase that real structure.

The existing inverse-alpha, residual-cleanup, detector, calibration, file handling and analysis-policy tests remain in the same suite.

## CI debugging history

### CI attempt 1 — run 31788682663

Result: **failure**, 23/24 tests passed.

Failure: the first directional-repair test used the existing pseudo-textured synthetic background. Its high local gradients intentionally activated the structure guard, so the repair correctly refused to modify much of the test band. The fixture mixed two separate requirements and did not isolate the intended smooth-halo behavior.

Action: split validation into a smooth-background repair test and a separate strong-structure preservation test.

### CI attempt 2 — run 31788754938

Result: **failure**, 24/25 tests passed.

- strong-structure preservation: PASS;
- smooth-background repair: FAIL.

Root cause: the original algorithm required valid low-alpha anchors on **both** normal directions. For a closed Gemini diamond, one normal direction points outward to background but the opposite direction usually enters the watermark body. Requiring both anchors caused most residual-edge pixels to be skipped.

Action: allow one-sided outward reconstruction. A single anchor receives reduced support; two anchors still use interpolation and cross-anchor consistency checking.

### CI attempt 3 — run 31788890574

Result: **failure**, 24/25 tests passed.

- smooth-background repair: PASS;
- strong-structure preservation: FAIL.

Root cause: the structure guard measured a symmetric gradient only at the current center pixel. A one-pixel bright line can have a near-zero symmetric derivative at its exact center while its neighboring pixels have very large gradients.

Action: replace the center-only structure measurement with the **maximum local gradient in a 3x3 neighborhood**, and make structure protection stronger in the final blend gate.

If real-video testing still leaves a visible outline after v1.0.12, the next quality tier should be a wider padded-ROI texture repair/inpaint backend or an optional ML denoise backend.
