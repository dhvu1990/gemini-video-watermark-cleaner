Failure:

- `npm test` — FAIL
- 179 tests passed, 1 failed.
- Failing test: `smooth rebuild reports diagnostics after the final reconstructed output` in `tests/adaptiveFinish.test.mjs`.
- The assertion expected `smoothBackground.applied === true`, but v1.0.82 correctly allowed the new detail-preservation guard to reject a smooth candidate and return the preserved input.

### Diagnosis

The failure was not a syntax or runtime defect. It exposed an outdated test contract: before v1.0.82, any branch classified as `smooth-rebuild` was expected to apply reconstruction. The new safety contract intentionally separates **classification** from **candidate acceptance**.

A frame may still be classified as smooth while the post-candidate preservation check rejects reconstruction because independent detail would be lost. In that case, the correct behavior is rollback rather than forcing the old assertion.

### Fix

Updated `tests/adaptiveFinish.test.mjs` so the test now validates both legitimate smooth-branch outcomes:

- if reconstruction is accepted, final diagnostics must come from `post-smooth-rebuild`;
- if reconstruction is rejected, diagnostics must show `detailPreservation.guardTriggered === true` and `reason === detail-preservation-reject`.

The final residual diagnostic must remain finite and within the established safety envelope in either case.

Fix commit:

- `0b71253595594359e7a0677c9137eea890e61f08` — `test: account for smooth detail preservation rollback`
