# v1.0.70 Accepted Structured Low-Gain Diagnostic — Phase 1

Date: 2026-08-18

## Objective

Use real v1.0.69 telemetry to close a diagnostics blind spot where a structured cleanup candidate can be accepted even though it leaves a visually obvious low-frequency diamond/shape footprint and only delivers a small aligned residual improvement.

This version is diagnostic-only. It does not change cleanup pixels, strengths, thresholds in the repair pipeline, masks, donor selection, atlas settings, calibration scoring, structured acceptance logic, or rollback behavior.

## Real telemetry that motivated this change

The user supplied a real structured-background sample with:
- temporal donor attempted: false
- atlas donors: 0
- structured attempted: true
- structured accepted: true
- accepted mode: `primary+shape-ghost`
- aligned before score: 1.720
- aligned after score: 1.635
- aligned sample density: 4.8%
- aligned improvement: 4.9%
- visible result: watermark body removed, but a low-frequency diamond/triangular tone-texture footprint remains.

This excluded temporal repair as the cause for this sample and exposed that `riskFlags` could still report `none` for an accepted structured cleanup with weak improvement and substantial residual density.

## Change

Modified `src/video/antiStreakDiagnostics.js` to add a new diagnostic-only risk flag:

`accepted-structured-low-gain`

The flag requires all of:
- structured stage attempted
- structured stage accepted
- aligned before score >= 1.45
- aligned sample density >= 0.03
- aligned improvement < 0.08

The summary also exposes `structured.acceptedLowGain`.

These thresholds are intentionally conservative and are not used to alter pixel output in v1.0.70.

## Tests

Updated `tests/antiStreakDiagnostics.test.mjs` with:
1. the real telemetry fixture `1.720 -> 1.635`, density `0.048`, improvement `0.049`, asserting the new flag is emitted;
2. a control fixture with the same before score/density but healthy improvement (`0.174`), asserting the new flag is not emitted;
3. preservation of all previous anti-streak diagnostics tests.

## Risk

The main risk is false-positive diagnostics if the thresholds are too broad. Because this version is diagnostic-only, a false positive can only affect the displayed risk flag, not the cleaned pixels.
