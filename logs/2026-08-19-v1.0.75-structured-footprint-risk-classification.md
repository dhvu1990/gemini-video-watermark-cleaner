# v1.0.75 — Provisional Structured Footprint Risk Classification

Date: 2026-08-19

## Objective

Turn the preview-visible structured-footprint telemetry repaired in v1.0.74 into a conservative diagnostic classification that separates likely hard residual footprint cases from borderline and clean/control cases without changing any cleanup pixels.

The target classes are:

- `STRONG` — multiple footprint signals agree that a broad watermark-shaped residual is likely still present;
- `SUSPECT` — several signals are elevated but do not meet the stronger multi-signal gate;
- `CLEAR` — the current metric does not satisfy the provisional footprint-risk gates;
- insufficient telemetry — not enough samples to classify.

This release is deliberately diagnostic-only. It does not increase structured cleanup strength, alter masks, change alpha calibration, modify temporal donor behavior, trigger a stronger cleanup pass, or affect exported pixels.

## Why v1.0.75 follows v1.0.74 instead of the abandoned v1.0.43 branch

During implementation, an earlier branch was created from a stale v1.0.42 base and a v1.0.43 center-seam PR was opened. The stale PR was therefore closed unmerged rather than rebased blindly:

- closed PR: #76
- stale branch: `agent/v1.0.43-center-seam`
- reason: superseded by current v1.0.74 architecture

A fresh branch was created from current `main`:

- branch: `agent/v1.0.75-structured-footprint`
- base: v1.0.74 commit `37c267ca8cfdab9bd9479a5790e358fd965a38ba`

This prevents old code from overwriting newer safety and telemetry work.

## Real visual evidence motivating classification

The latest reviewed sample group contains three useful visual categories:

1. visually clean controls, especially several 720 Relocated cases where the Gemini footprint is effectively absent;
2. borderline cases where only a faint footprint remains;
3. hard dark/structured cases where the cleaned preview still shows a broad dark diamond-like footprint.

Prior real telemetry also demonstrated a hard brown/black structured case where ordinary metrics reported improvement and structured acceptance even though a broad footprint remained visually obvious. v1.0.74 fixed the missing runtime alpha-map bridge so the dedicated footprint metric can now be observed reliably.

The immediate need is therefore classification/observability, not another unconditional cleanup-strength increase.

## New module: `src/video/structuredFootprintRisk.js`

Added `classifyStructuredFootprintRisk(metric, options)`.

The classifier consumes the already-computed v1.0.72/v1.0.73 footprint telemetry:

- `score`
- `rawScore`
- `coverage`
- `shapeAlignedDensity`
- `continuityMean`
- `samples`
- `candidateSamples`

It derives four normalized evidence signals:

1. footprint score signal;
2. shape-aligned density signal;
3. spatial coverage signal;
4. retained score ratio after continuity discount.

A continuity-confidence factor slightly reduces evidence when the apparent residual strongly continues into the surrounding real scene.

## Provisional thresholds

The thresholds are intentionally multi-signal and conservative. They are explicitly marked provisional because the repository still needs additional real v1.0.75 telemetry from the known hard/borderline/clean samples before any cleanup behavior is allowed to depend on them.

### STRONG

All of the following must hold:

- score >= `1.25`
- shape-aligned density >= `1.2%`
- coverage >= `1.8%`
- continuity mean <= `55%`
- combined evidence >= `68%`

### SUSPECT

All of the following must hold:

- score >= `0.70`
- shape-aligned density >= `0.4%`
- coverage >= `0.8%`
- continuity mean <= `72%`
- combined evidence >= `38%`

### Minimum measurement gate

Classification is withheld when:

- samples < `8`, or
- candidate samples < `12`.

This prevents a few isolated pixels from becoming a footprint verdict.

## Scene-continuity safety

The classifier builds on the corrected v1.0.73 footprint continuity probe, which follows the tangent of a low-frequency real image edge into clean pixels outside the watermark footprint.

High continuation through the real scene therefore blocks `STRONG`/`SUSPECT` classification through the continuity limits above. The classifier also reports a `scene-continuity` reason when that condition is present.

This is important for protecting legitimate scene boundaries such as:

- wall/furniture edges;
- door/window lines;
- table or shelf boundaries;
- large text strokes;
- other real structured features crossing the watermark area.

## Evidence score

The provisional evidence score combines normalized signals with these weights:

- footprint score: 42%
- shape-aligned density: 28%
- coverage: 16%
- retained score ratio: 14%

The result is then modulated slightly by scene-continuity confidence.

The evidence score is intended for diagnosis and threshold tuning. It is not a probability and must not be interpreted as a calibrated statistical confidence value.

## Safety statement

Expected cleanup and export pixels are unchanged in v1.0.75.

This release does **not**:

- add `structured-footprint-strong` to export risk counters;
- alter structured ring acceptance;
- alter shape-ghost strength;
- alter center-seam/local-tone/outer-halo strength;
- alter downstream rollback;
- alter temporal donor/atlas logic;
- perform a second cleanup pass based on the new class.

The classification is intentionally observational until real data confirms useful separation.

## Required real validation after merge

Run the same sample set on v1.0.75 and record these eight fields for each sample:

1. Footprint score
2. Footprint raw
3. Footprint coverage
4. Shape-aligned density
5. Continuity discount
6. Footprint class
7. Evidence
8. Class reason

Minimum validation set:

- both visually hard dark/structured footprint samples;
- at least one borderline faint-footprint sample;
- at least two visually clean 720 Relocated controls;
- ideally one scene-edge control with a legitimate strong boundary through the ROI.

Desired separation before behavioral use:

- hard cases should normally become `STRONG`;
- borderline cases should normally be `SUSPECT` or low-evidence `STRONG` only if visual review confirms the footprint;
- clean controls should remain `CLEAR`;
- real scene-edge controls should not become `STRONG` because continuity should discount them.

## Planned next step only after real validation

If the above separation is confirmed, a later release may use `STRONG` as a gate for a narrowly stronger reconstruction/rollback decision. `SUSPECT` should initially remain diagnostic-only.

If clean controls are misclassified, tune classifier thresholds first rather than increasing cleanup strength.
