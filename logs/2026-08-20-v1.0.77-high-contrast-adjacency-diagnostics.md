# v1.0.77 — High-Contrast Scene-Edge Adjacency Diagnostics

Date: 2026-08-20

## Objective

Add a conservative, diagnostic-only measurement for the difficult real preview class where the Gemini watermark footprint overlaps or sits immediately beside strong scene structure such as white text, glyph strokes, borders, or other high-contrast edges.

This release does **not** increase cleanup strength and does **not** modify exported pixels. Its purpose is to collect reliable evidence before introducing a text-/scene-edge-aware cleanup policy in a later release.

## Real visual trigger

Recent real preview review produced two especially useful cases:

1. a blue structured background with a bright diagonal streak that currently cleans well and preserves the scene line;
2. a brown/dark background near strong white text where the cleaned preview still shows a visible diamond footprint and center-seam-like residual.

The second case is dangerous for an unconditional stronger pass. A real glyph edge can be locally stronger than the watermark residual, and a global strength increase could erase or smear legitimate text while improving the diamond.

The correct next step is therefore to measure **high-contrast adjacency around the alpha footprint** separately from the existing watermark-shaped residual metrics.

## Relationship to v1.0.75 and v1.0.76

v1.0.75 introduced provisional structured-footprint classification (`STRONG`, `SUSPECT`, `CLEAR`) from watermark-shape evidence and scene-continuity discounting.

v1.0.76 addressed a separate smooth-background issue: near-neutral white/gray surfaces receiving a yellow/green/cyan chroma cast during smooth reconstruction.

v1.0.77 complements those releases. It does not replace the footprint classifier. Instead, it answers a different question:

> Is there a strong real-looking scene edge immediately adjacent to or crossing the watermark footprint, such that future stronger cleanup should protect that structure?

### Measurement design

The module operates on the final cleaned preview plus the calibrated alpha map.

It intentionally avoids OCR. The diagnostic is a **high-contrast scene-edge adjacency proxy**, not a semantic text detector.

The algorithm:

1. builds a small low-pass luma field to suppress one-pixel noise while retaining glyph/border edges;
2. searches only clean/exterior pixels close to the watermark alpha footprint;
3. measures strong local luma gradients;
4. measures whether those gradients straddle the mask neighborhood;
5. finds the nearest alpha gradient and measures image-edge/alfa-shape alignment;
6. discounts edge evidence that strongly follows the watermark alpha contour, because that is more likely to be watermark-shaped residual than a real independent scene edge;
7. combines density, straddle evidence, contrast magnitude, and scene-edge-weight evidence into a bounded diagnostic score.

### Returned metrics

The metric includes:

- `score`
- `edgeDensity`
- `straddleDensity`
- `meanContrast`
- `p90Contrast`
- `shapeAlignment`
- `sceneEdgeWeight`
- `candidateSamples`
- `edgeSamples`
- `straddleSamples`

These values are intentionally retained as raw telemetry so threshold tuning can be based on real B1/control samples rather than synthetic assumptions alone.

## Provisional classification

The module includes a conservative provisional classifier:

### HIGH

Requires all of:

- score >= `0.52`
- edge density >= `5.5%`
- straddle density >= `1.2%`
- mean contrast >= `5.5`

### MEDIUM

Requires all of:

- score >= `0.25`
- edge density >= `2.2%`
- straddle density >= `0.4%`
- mean contrast >= `3.2`

### Minimum sample gate

- candidate samples >= `20`

Below that, classification is `insufficient`.

These thresholds are **provisional** and must not drive pixel modification until validated against the fixed real benchmark.

## Explicit non-goals

v1.0.77 intentionally does **not**:

- run OCR;
- identify semantic text characters;
- modify center-seam strength;
- modify structured-ring strength;
- modify shape-ghost strength;
- modify local-tone or outer-halo strength;
- change temporal donor or atlas behavior;
- change calibration scoring;
- change smooth-background reconstruction;
- use adjacency classification to alter exported pixels.

## Why no stronger cleanup yet

The brown/text sample demonstrates that more aggressive cleanup is needed somewhere, but the clean blue diagonal-line sample demonstrates that legitimate scene structure is currently being preserved well.

A stronger pass without an adjacency guard risks trading one visible watermark artifact for damaged real text/edges.

v1.0.77 therefore collects the missing separation signal first.

## Desired real-data separation

The desired pattern is:

- brown/text hard case: footprint `STRONG` or `SUSPECT`, plus adjacency `HIGH` or clearly elevated;
- blue diagonal-line clean control: footprint low/clear and/or adjacency evidence that correctly reflects the real line without creating a false watermark verdict;
- clean relocated controls: low footprint risk and low/medium adjacency unless a real high-contrast edge is physically present;
- smooth near-neutral control: low adjacency.

## Planned follow-up only after validation

If real telemetry separates the cases reliably, the next behavioral release can introduce a **protected structured residual cleanup** rule rather than a global strength increase.

A likely policy is:

- footprint `STRONG` + adjacency low -> allow a narrowly stronger watermark reconstruction;
- footprint `STRONG` + adjacency high -> protect real high-contrast structure and restrict stronger correction to watermark-shape-supported pixels away from scene-edge evidence;
- footprint `CLEAR` -> do not add an extra cleanup pass.

If the brown/text case does not show elevated adjacency, tune diagnostics first. Do not increase cleanup strength based on an unvalidated classifier.
