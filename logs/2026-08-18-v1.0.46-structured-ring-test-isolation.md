# v1.0.46 — Structured ring regression isolation

## Context
PR #46 (v1.0.45 runtime center-seam integration) reached GitHub Actions CI run #527. Syntax checks passed and the new center-seam runtime integration tests passed, but the full test suite finished 91/92 because one existing structured-ring test still assumed that an accepted result could only report `primary` or `micro-salvage`.

## Failure observed
- Workflow run: `32078587638`
- Job: `95536846150`
- `npm run check`: PASS
- `npm test`: FAIL, 91 passed / 1 failed
- Failing test: `tests/structuredRingSuppress.test.mjs`
- Assertion expected `acceptedMode` to be only `primary` or `micro-salvage`.

The runtime change in v1.0.45 intentionally appends/runs Center Seam after ring/shape finishing. Therefore the old ring-unit test was no longer truly isolating the ring pass. The algorithm itself was not shown to regress by this failure.

## Correction
The structured-ring unit tests now explicitly pass `centerSeam: false` wherever they are testing ring-only or micro-salvage-only semantics. This preserves the historical ring safety assertion while leaving the new runtime integration coverage responsible for validating Center Seam.

This is preferable to widening the old assertion to accept `+center-seam`, because that would silently mix two different responsibilities in one unit test and weaken regression diagnosis.

## Version policy
This corrective repository edit is released as v1.0.46 rather than modifying v1.0.45 in place.
