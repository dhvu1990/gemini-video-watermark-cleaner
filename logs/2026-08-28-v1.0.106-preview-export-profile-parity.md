## Root cause in v1.0.105

The detector and export paths did not carry the same per-video calibration state explicitly.

### Preview path

`inspectVideo()` receives the detector's refined `internalDetection.alphaMap` and detector-calibrated `alphaGain`. `createDetectionPreview()` passes that exact map and gain into `repairPaddedRegion()`. Therefore the preview reflects the current file's calibrated detector profile.

### Batch export path

`prepareInspectResultForWorker()` preserves the diagnostic alpha map as `internalDetection.alphaMap`, but `src/batch-ui.js` previously stored only the public detection and preview. The per-file alpha map was discarded.

When the cached batch detection was later reused for `Clean all`, `processOptions()` sent only the detected region and the global UI alpha gain. It did not send the per-file calibrated alpha map or, when the UI remained at its default value, the per-file detector-calibrated gain.

### Cross-item active calibration leakage

`src/video/alpha.js` also maintains `ACTIVE_CALIBRATION`, keyed only by watermark size. `detectVideoWatermarkFromFrames()` calls `setActiveAlphaCalibration(size, calibration.alphaMap, calibration)` whenever calibration succeeds.

In `cleanVideo()`, a supplied `detectedRegion` previously caused this call:

`getVideoAlphaMap(position.width)`

Because this is `profile='auto'` with zero edge boost, `getVideoAlphaMap()` may return `ACTIVE_CALIBRATION[size]`.

All six current test scenes use the same 72x72 watermark size. Sequential batch preview inspection can therefore overwrite the single active 72x72 calibration. Later exports that reuse cached detections can receive whichever same-size calibration was left active most recently, rather than the alpha map that produced each file's preview.

This is a concrete cross-item state leak and preview/export parity defect. It is a stronger and safer next target than globally weakening scene-edge protection or increasing cleanup strength.

## v1.0.106 implementation

### 1. Explicit per-video alpha-map reuse

New helper module: `src/video/detectionProfileReuse.js`.

It validates and clones a detector alpha map before export reuse. Validation requires exact geometry and finite alpha values within [0, 1]. Invalid data is rejected rather than trusted.

Batch preview analysis now stores each item's `internalDetection.alphaMap` separately and forwards it to the process worker together with that item's cached detected region.

Single-video export now also forwards the inspected alpha map explicitly instead of relying on worker-global active calibration state.

### 2. Deterministic safe fallback

When a detected-region export does not have a valid cached map, `cleanVideo()` now asks for an explicit embedded base profile (`48` for compact sizes or `96-20260520` otherwise) rather than calling auto-profile lookup. This avoids consulting the mutable `ACTIVE_CALIBRATION` map.

Manual-region export also uses the deterministic embedded base profile, preventing unrelated prior detection state from leaking into manual cleanup.

No detector threshold is lowered. No scene-edge threshold is weakened. No global alpha gain, edge polish, blur, reconstruction strength or ROI size is increased.

### 3. Per-file detector gain in batch

If the batch alpha-gain UI remains at its default 1.0, export uses that file's detector-calibrated `detection.alphaGain`.

If the operator explicitly changes the alpha-gain control away from 1.0, the operator value remains authoritative and is not silently overwritten.

Single-video behavior already synchronizes the UI gain from detection and remains compatible with this rule.

### 4. Export telemetry

Export metadata now reports `alphaMapSource`, including:

- `cached-detection`
- `fresh-detection`
- `base-profile-fallback`
- `invalid-cached-fallback`
- `manual-base-profile`

This makes future preview/export parity failures directly observable instead of implicit.

## Test coverage

New `tests/detectionProfileReuse.test.mjs` covers:

- exact-geometry alpha-map cloning;
- invalid length rejection;
- non-finite/out-of-range rejection;
- deterministic embedded-profile selection;
- direct proof that an explicit fallback profile ignores a deliberately poisoned same-size `ACTIVE_CALIBRATION` entry;
- detector gain reuse when the UI remains at default;
- explicit operator gain override;
- missing detector gain safely falls back to the configured/default gain.

New `tests/previewExportProfileParity.test.mjs` locks the wiring that:

- batch preview stores each item's internal alpha map;
- cached batch export forwards the per-item map;
- batch default gain follows per-file detector calibration;
- single-video export forwards the inspected alpha map;
- detected-region export validates the cached map;
- fallback uses an explicit embedded profile rather than active auto calibration.
