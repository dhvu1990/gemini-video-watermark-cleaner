# v1.0.5 - Browser file selection incident

Date: 2026-08-14

## User-visible symptom

On the deployed GitHub Pages site, selecting a Gemini/Veo video from Chrome on Windows appeared to freeze or do nothing:

- the file picker closed,
- the page still displayed `No video selected.`,
- `Analyze watermark` remained disabled,
- no obvious error appeared near the upload area.

The report was received during the first real production browser regression test after GitHub Pages deployment became successful.

## Production state when reported

- Production URL: `https://dhvu1990.github.io/gemini-video-watermark-cleaner/`
- Stable main version before fix: v1.0.4
- Main commit before fix: `250508579ad56fc458fdd38caf0a444e9417a179`
- Successful Pages deployment used for the first live test: workflow run `31775076589`
- That deployment had passed build and deploy end-to-end.

The screenshot also exposed a separate presentation defect: the rendered app badge/title still showed `v1.0.0` even though package/README had reached v1.0.4. This was caused by hard-coded version text in `index.html` not being updated during prior version bumps.

## Root-cause analysis

The v1.0.4 `useFile()` function rejected every selected file unless the browser-provided MIME type started with `video/`:

```js
if (!nextFile.type.startsWith('video/')) {
  setStatus('Please choose a video file.');
  return;
}
```

This was too strict for local browser files. Depending on OS/browser/file registration, a valid MP4/MOV can arrive with:

- an empty `File.type`, or
- a non-standard/unknown MIME value.

When that happened, the file was rejected before being assigned to application state. The rejection message was written only to the bottom `status` element in the Export section, while the upload area continued to say `No video selected.` Therefore the behavior looked like a frozen UI even though the JavaScript had actually rejected the input.

A second UX weakness was that the file input was hidden inside a clickable label/drop area. Although valid HTML, it gave no explicit post-selection feedback and made the failure mode harder to understand.

## v1.0.5 correction

Created branch:

- `agent/v1.0.5`

Implemented:

1. Added `src/video/file.js` with explicit file validation helpers.
2. Accept a file when either:
   - MIME starts with `video/`, or
   - filename extension is one of `.mp4`, `.mov`, `.m4v`, `.webm`.
3. Reject zero-byte files with a dedicated error.
4. Show validation errors directly beside the file-selection area.
5. Added an explicit **Choose video** button that calls the native file picker.
6. Preserve drag-and-drop support.
7. Reset the native input value before each picker invocation so selecting the same file again still triggers `change`.
8. Updated `accept` to `video/*,.mp4,.mov,.m4v,.webm`.
9. Updated hard-coded document title and visible badge to `v1.0.5`.
10. Added `src/video/file.js` to `npm run check`.

## New tests

Added `tests/file.test.mjs` covering:

- normal `video/mp4` MIME acceptance,
- `.mp4` acceptance when MIME is empty,
- `.mov`, `.m4v`, `.webm` extension fallback,
- unrelated file rejection,
- zero-byte video rejection,
- extension and file-size helper behavior.

The pre-existing suite had 5 tests, so v1.0.5 is expected to run 11 tests before merge.
