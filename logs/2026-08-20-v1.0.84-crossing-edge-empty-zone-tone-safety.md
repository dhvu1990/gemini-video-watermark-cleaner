# v1.0.84 — Crossing scene-edge protection, empty-zone safety rewrite, tone protection

Date: 2026-08-20
Branch: `agent/v1.0.84`
Base: `main` at v1.0.83 (`d935904852c181b17115839ab9dd5f4b15da0334`)

## Real-video trigger

The latest seven-scene preview batch exposed three high-priority failure classes that were not safe to solve by globally increasing cleanup strength:

1. **scene7 — destructive empty-zone hard suppression**
   - the cleaned result became an unnaturally flat blue patch;
   - real scene gradient/detail was removed together with the watermark footprint;
   - this is considered more severe than leaving a faint residual because it fabricates image content.

2. **scene1 — strong diagonal scene edge crossing the watermark ROI**
   - cleanup left a vertical/tone smear around the watermark area;
   - the real diagonal edge must be treated as scene structure rather than watermark geometry;
   - footprint-wide tone correction is unsafe when a coherent non-watermark edge crosses the mask.

3. **scene3/scene4/scene5 — smooth blue tone footprint**
   - watermark body removal is largely successful;
   - the remaining visible failure is a local tone/gradient mismatch rather than only a ring;
   - correction must remain anchor/plane-based and conservative, with explicit protection for real crossing edges.

Regression guards from the same batch:

- scene2 — visually strong result; do not regress.
- scene6 — textured/dark structured case is comparatively stable; do not increase global ring strength.

## Design decision

v1.0.84 is a **safety-first refinement**. It does not add another broad blur/inpaint system and does not globally increase ring strength.

The release focuses on:

- detecting real scene edges that cross the watermark footprint;
- using that evidence to block destructive hard suppression and footprint-wide tone correction;
- making the existing empty-zone hard path much harder to enter;
- requiring stronger final detail retention before accepting a hard candidate;
- preserving the v1.0.83 quadrant-aware local tone field for genuinely smooth, low-risk cases.

## Change 1 — `sceneEdgeProtection.js`

New file: `src/video/sceneEdgeProtection.js`

### Per-pixel signal

`sceneEdgeProtectionAt()` measures:

- image luma gradient magnitude;
- alpha-mask gradient magnitude;
- image/alpha gradient alignment;
- tangent-direction continuity of the image edge on both sides of the sample;
- alpha-band eligibility.

Interpretation:

- an edge strongly aligned with the alpha contour is more likely watermark-shaped and receives low scene-protection weight;
- a strong edge that is not aligned with the alpha contour receives higher protection weight;
- continuity along the scene edge raises confidence that the edge is real scene structure rather than a local watermark artifact.

### ROI-level signal

`measureCrossingSceneEdgeRisk()` aggregates protected samples and reports:

- `score`;
- `level`: `insufficient`, `low`, `medium`, or `high`;
- `protect` boolean;
- candidate sample count;
- scene-edge sample count;
- continuous scene-edge sample count;
- scene-edge density;
- continuity density;
- mean gradient;
- mean alpha-shape alignment.

The thresholds are intentionally conservative. Protection is only asserted when enough evidence exists across the footprint.

## Change 2 — empty-zone hard suppression safety rewrite

File: `src/video/emptyZoneHardSuppress.js`

### Stricter entry classification

Default near-empty limits changed from the previous permissive values to:

- complexity <= `0.16`;
- surface MAE <= `3.8`;
- edge density <= `0.012`;
- mean gradient <= `3.2`;
- mean Laplacian <= `3.2`;
- core structure density <= `0.06`.

This intentionally makes the hard path rare. A normal smooth rebuild remains available through the regular smooth pipeline; the *hard* double rebuild is now reserved for exceptionally low-energy fields.

### Crossing-edge veto

Before rendering a hard candidate, the module now calls `measureCrossingSceneEdgeRisk()`.

If `crossingEdge.protect === true`:

- the hard pass is not attempted;
- the input image is returned unchanged;
- diagnostic reason is `crossing-scene-edge-protection`.

### Reduced second hard pass

The second smooth reconstruction is no longer a second unrestricted full-strength rebuild by default.

New defaults:

- first pass dilation radius: `5` instead of `6`;
- first micro-smooth: `0.22` instead of `0.28`;
- second strength: `0.82` instead of `1.0`;
- second dilation radius: `5` instead of `7`;
- second micro-smooth: `0.20` instead of `0.30`.

### Final detail-preservation gate

After the second candidate is built, v1.0.84 performs a new end-to-end preservation comparison between the hard-pass input and the final candidate using `evaluateSmoothDetailPreservation()`.

Default final retention requirements:

- gradient retention >= `0.82`;
- Laplacian retention >= `0.78`;
- edge-density retention >= `0.74`.

The evidence thresholds are lower than the normal smooth guard so even low-contrast scene detail can become eligible for preservation checking.

A candidate is accepted only when:

- final detail preservation passes;
- total cleanup residual improves to <= `0.994` of baseline;
- luma residual stays <= `1.012` of baseline;
- chroma residual stays <= `1.045` of baseline.

Rejected candidates are rolled back completely.

## Change 3 — crossing-edge protection for local tone matching

File: `src/video/localToneMatch.js`

v1.0.83 already introduced a quadrant-aware local tone field built from clean exterior reference samples and a robust fitted plane.

v1.0.84 preserves that architecture, but adds an ROI-level crossing-scene-edge safety gate before footprint-wide tone correction.

If a coherent scene edge crosses the footprint:

- local tone correction is not attempted;
- no global/quadrant/local luma shift is applied;
- the image is returned unchanged;
- diagnostic reason is `crossing-scene-edge-protection`;
- the full `crossingEdge` diagnostic is retained for inspection.

Why ROI-level veto instead of weakening only a few pixels:

The problematic scene1 behavior is not just a single edge pixel. A fitted tone field can drag the surrounding patch toward the plane and create a visible smear around a genuine line. If a strong crossing edge exists, the safer strategy is to leave tone cleanup to shape-local structured passes rather than applying a footprint-wide field correction.

## Safety philosophy

v1.0.84 follows these rules:

1. preserving real scene content has priority over removing the last faint watermark trace;
2. real edge evidence can veto broad reconstruction/correction;
3. hard smooth reconstruction must be rarer than normal smooth reconstruction;
4. every destructive candidate remains try-measure-accept with complete rollback on failure;
5. no global cleanup-strength increase is introduced for scene2/scene6 regression safety.
