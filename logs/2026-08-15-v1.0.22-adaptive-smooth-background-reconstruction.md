# v1.0.22 — Adaptive Smooth-Background Reconstruction

Date: 2026-08-15

## Motivation

Real-video validation of v1.0.21 showed two distinct classes of scenes:

1. A textured keyboard/laptop background where preserving real structure is essential and aggressive blur/rebuild would be unsafe.
2. A smooth blue USB-C background where the visible Gemini outline remained faintly detectable even though there was no meaningful text/object detail under or around the watermark.

The user proposed using stronger blur for the easy case. The implementation adopts the underlying idea but uses a safer reconstruction path: classify the local background first, rebuild the full watermark footprint from a fitted smooth background surface, feather the transition, then use only a small transition blur.

## Design goals

- Keep the v1.0.21 structured/detail-preserving path unchanged for complex backgrounds.
- Detect when the watermark sits on an empty/smooth/gradient background.
- Allow an aggressive full-footprint replacement only for those safe backgrounds.
- Avoid a visible rectangular or diamond patch by fitting the surrounding background and feathering beyond the alpha footprint.
- Keep preview and exported MP4 on the exact same finishing path.
- Expose classifier diagnostics in the UI for real-video threshold tuning.

## Implementation

### New module

`src/video/smoothBackground.js`

### Background surface fit

The module fits a 2D quadratic RGB surface using only clean pixels outside the watermark alpha footprint.

Basis:
- constant
- x
- y
- x^2
- x*y
- y^2

This can model flat colors, linear gradients and gentle curved illumination without copying the watermark itself into the fit.

### Safety classifier

`analyzeSmoothBackground()` evaluates:

- quadratic surface fit MAE,
- exterior edge density,
- mean gradient energy,
- mean Laplacian/high-frequency energy,
- structure density inside the footprint that does not align with the watermark alpha geometry,
- a combined complexity score.

Default safety gates:

- complexity <= 0.43
- surface MAE <= 10.5
- edge density <= 0.13
- mean gradient <= 11.5
- mean Laplacian <= 8.5
- core structure density <= 0.24

All gates must pass before aggressive reconstruction is allowed.

### Aggressive smooth-background reconstruction

When safe:

1. Build a dilated/feathered mask from the full alpha footprint and low-alpha halo.
2. Evaluate the fitted RGB surface inside the footprint.
3. Replace almost the full watermark body/edge with the fitted background.
4. Feather the replacement into the surrounding clean pixels.
5. Apply only a small 3x3 micro-smooth pass in the transition band.

This is intentionally different from whole-ROI blur: the expected background is reconstructed first, and blur is limited to the blend boundary.

### Structured fallback

If any classifier gate fails, no smooth rebuild is applied. The output remains the existing v1.0.21 path:

- inverse alpha,
- padded texture repair,
- multi-frame atlas / temporal donor,
- normal edge bridge,
- dual-ring luma finish,
- residual-aware selective second pass.

### Integration

The adaptive branch is called inside `applyDualRingLumaFinish()` after the v1.0.21 finishing logic. Because detection preview and full-video export already share this function, both paths use identical classification/reconstruction behavior.

### Diagnostics

The Tune panel now shows:

- Background mode (`smooth-rebuild` or `structured`)
- Complexity score
- Surface fit MAE
- Edge density

The preview note also states whether smooth rebuild or structured fallback was selected.

## Regression coverage

Added `tests/smoothBackground.test.mjs`:

1. Smooth gradient background:
   - must be classified safe,
   - must select `smooth-rebuild`,
   - full-footprint reconstruction must reduce synthetic watermark MAE strongly.
2. Keyboard-like structured background:
   - must be rejected,
   - must select `structured`,
   - at least one structure/complexity safety gate must fail.

## Expected real-video behavior

### USB-C smooth/gradient sample

Expected: `smooth-rebuild` if the real ROI satisfies all safety gates. The faint Gemini outline should be substantially reduced or visually eliminated because the whole footprint is rebuilt instead of only edge-corrected.

### Keyboard/textured sample

Expected: `structured`. Aggressive smooth rebuild must not run; detail-preserving v1.0.21 behavior remains active.

## Important limitation

The classifier is deliberately conservative. A smooth-looking scene that contains a real edge/object crossing the ROI should be rejected rather than aggressively rebuilt. The thresholds will be tuned only from real-video validation and regression evidence, not by weakening safety gates blindly.
