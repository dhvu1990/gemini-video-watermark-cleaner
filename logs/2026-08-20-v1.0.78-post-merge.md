## Problems addressed

1. intermittent `Error: network error` during multi-file batch processing;
2. excessive module-worker recreation: one Inspect worker + one Process worker for every file;
3. Retry button did not work while the batch was still active because `retryItem()` rejected `state.running` and `Clean all` was disabled;
4. single-video `Clean video` action was too far down the page, requiring repeated scrolling through diagnostics.

## Delivered behavior

- one persistent batch worker is reused across sequential Inspect/Process operations;
- transport/network/module-load errors get up to two bounded automatic retries;
- a transient output-folder save receives one bounded retry;
- manual Retry can queue a failed/cancelled item while a later item is processing;
- after the active item completes, a queued retry starts a fresh queue pass and earlier failed items regain priority by original row order;
- single-video `Quick clean / Export` is moved directly below the video chooser;
- Batch Processing is mounted directly below Quick clean / Export;
- no watermark-cleaning pixel algorithm was changed.

## Follow-up rule

If the same `network error` still appears frequently after v1.0.78, record:

- whether the failure occurs during Detecting, Cleaning, or Saving;
- the exact row status immediately before failure;
- whether automatic reconnect appears;
- whether Retry queued successfully re-runs the item;
- browser/runtime environment.

That evidence should be used to isolate any remaining browser/platform source instead of increasing retry loops globally.
