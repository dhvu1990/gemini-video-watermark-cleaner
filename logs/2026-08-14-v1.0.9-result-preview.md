# v1.0.9 - Cleaned Result Preview

Date: 2026-08-14
Repository: `dhvu1990/gemini-video-watermark-cleaner`
Branch: `agent/v1.0.9`

## User request

After a successful `Clean video` export, the web interface previously exposed only the progress/result text and `Download cleaned MP4`. The requested change is to add a Result area that can play the generated cleaned video directly in the browser, similar to the visual review workflow already provided by Auto Detection Preview.

## Scope decision

This release is intentionally limited to result-review UX. The validated v1.0.8 detector, alpha map, inverse-alpha restoration, residual footprint cleanup, temporal stabilization, MediaBunny/WebCodecs export, and audio behavior are not modified.

## Implementation

### 1. New Result panel

A new `4. Result preview` section is added immediately below Export. It remains hidden until a successful process result is received from the Worker.

The panel includes:

- `CLEANED RESULT` heading;
- a native HTML video player;
- normal browser controls for play/pause, timeline seek, volume and fullscreen where supported;
- a compact result summary showing processed/skipped frame counts;
- a caption clarifying that the generated video is local to the browser.

### 2. Shared local Blob URL

The Worker still returns the encoded MP4 buffer exactly as before. The main thread creates a single `video/mp4` Blob and one `URL.createObjectURL()` URL.

That same URL is used for both:

- the existing `Download cleaned MP4` link; and
- the new Result video player.

No second encode, upload, network request or duplicate media buffer is introduced by the preview feature.

### 3. Lifecycle and memory safety

A centralized `resetOutputPreview()` routine now owns result cleanup. It:

- pauses the old result video;
- removes its `src` and reloads the element;
- hides the Result panel;
- clears the old download href;
- revokes the previous Blob URL;
- restores the waiting result text.

It is invoked when:

- a different source video is selected;
- file selection is cleared/invalidated;
- the user starts another clean pass;
- a new process result replaces an older result.

The normal `beforeunload` cleanup remains as a final safety net.

### 4. Post-export behavior

When `process-result` arrives:

1. stale output is cleared;
2. the new MP4 Blob URL is created;
3. Download is enabled;
4. the Result player receives the same URL;
5. the Result panel becomes visible;
6. processed/skipped frame counts are shown;
7. the page smoothly scrolls to the Result panel.

The video is not autoplayed. The user explicitly starts playback.

### 5. Layout

The result player is centered in a bordered dark container consistent with Auto Detection Preview. Desktop width is capped for visual balance, while mobile/tablet layouts shrink responsively. Video uses `object-fit: contain` and a viewport-relative maximum height so portrait and landscape results remain reviewable without distorting aspect ratio.

## Versioning

Because this repository increments version for every project edit, the package, page title, badge and README are bumped from `v1.0.8` to `v1.0.9`.

## Validation gate

Before merge, GitHub Actions must pass:

- pinned alpha sync;
- syntax checks;
- all existing unit tests;
- Vite production build.

No detector/cleanup regression tests are expected to change because the media algorithm is unchanged. After merge, the GitHub Pages deployment must complete successfully before production is considered updated.

## Browser regression checklist

1. Refresh production and verify badge `v1.0.9`.
2. Select the existing `scene1.mp4` regression sample.
3. Confirm Auto Detection Preview still behaves as v1.0.8.
4. Click `Clean video`.
5. Confirm the Result panel is hidden while processing.
6. Confirm it appears after export completes.
7. Play and seek the cleaned video directly in the new player.
8. Confirm `Download cleaned MP4` still downloads the same result.
9. Select another source video and confirm the previous Result panel/player is cleared.
10. Clean again and confirm only the newest result remains active.

## Expected user impact

The cleanup workflow becomes review-first instead of download-first: users can inspect the final encoded video inside the tool and only download after confirming that watermark cleanup and playback look acceptable.
