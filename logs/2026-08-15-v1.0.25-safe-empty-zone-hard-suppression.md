# v1.0.25 — Safe Empty-Zone Hard Suppression

Date: 2026-08-15

## Motivation

Real-video validation of v1.0.24 confirmed that the adaptive split is correct:

- the USB-C sample is classified as a smooth/near-empty background and already cleans extremely well,
- the keyboard sample is classified as structured and must keep the detail-preserving fallback.

The remaining opportunity is to be more aggressive only when the watermark footprint and its surrounding area are genuinely empty or near-empty: no text, object boundary, strong edge, or structured texture that must be preserved.

## Goal

Add a stricter second safety gate inside the existing smooth-background branch. When the background is not merely `smooth-safe` but specifically `near-empty`, allow a stronger full-footprint reconstruction to eliminate the last faint ring/halo. Structured content must never enter this path.

## New module

`src/video/emptyZoneHardSuppress.js`

### `classifyNearEmptyBackground()`

Uses stricter limits than the existing smooth classifier.

Default limits:

- complexity <= 0.22,
- surface-fit MAE <= 5.5,
- edge density <= 0.025,
- mean gradient <= 6.5,
- mean Laplacian <= 5.0,
- core-structure density <= 0.10.

A frame is eligible only when the existing smooth classifier already marked it safe and all near-empty limits also pass.

### `applySafeEmptyZoneHardSuppression()`

For eligible near-empty backgrounds only:

1. measures post-clean residual before the hard pass,
2. runs a full-strength background reconstruction with a wider dilation/feather footprint,
3. runs a second full-strength reconstruction to drive the ROI closer to the fitted clean background surface,
4. uses stronger transition micro-smoothing only on the feather zone,
5. measures the candidate residual,
6. accepts the candidate only when total residual improves and luma/chroma do not become materially worse.

If the candidate fails the quality gate, the exact incoming smooth-rebuild image is preserved.

## Adaptive branch behavior

`applyDualRingLumaFinish()` now has three final outcomes:

1. `empty-hard-rebuild`
   - requires the normal smooth classifier to pass,
   - requires the stricter near-empty classifier to pass,
   - requires the hard candidate to pass residual acceptance.

2. `smooth-rebuild`
   - used when the background is smooth-safe but not near-empty enough for the hard pass, or the hard candidate is rejected.

3. `structured`
   - continues to use the v1.0.24 structured residual ring suppression and detail-preserving fallback.

The structured branch is isolated from empty-zone hard suppression.

## Diagnostics

The Adaptive background diagnostics card now exposes:

- Background mode,
- Complexity score,
- Surface fit MAE,
- Edge density,
- Empty-zone eligible,
- Hard attempted,
- Hard accepted,
- Hard candidate residual,
- Hard improvement,
- Structured attempted,
- Structured accepted,
- Structured candidate residual.

This makes it possible to distinguish classifier behavior from candidate accept/reject behavior during real-video tuning.

## Safety principles

- No whole-ROI blur on structured content.
- Near-empty hard suppression is stricter than ordinary smooth rebuild.
- Hard reconstruction remains try-and-accept.
- Structured keyboard-like content keeps the detail-preserving path.
- The hard path is intended for visually empty or gradient-only regions where removing the entire watermark footprint is safer than preserving local detail.
