# v1.0.50 — Guarded thin outer-halo suppression Phase 1

## Context

PR #50 (`v1.0.49: local tone runtime + CI test isolation fix`) passed the full GitHub Actions pipeline in CI run #555:
- alpha asset sync: pass
- syntax check: pass
- tests: pass
- build: pass

PR #50 was squash-merged to `main` at commit `8e3361ef0265bad1bdac5fa72cc748d398fc85fc`.

With Center Seam and Local Tone Match now runtime-integrated, the next remaining visual issue from the comparison screenshots is a very thin watermark-shaped halo that can sit just outside the nominal alpha footprint.

This is intentionally treated as a separate problem. Increasing the existing ring strength globally would risk repainting detailed backgrounds, especially the yellow/blue sample that previously showed streak artifacts.

## Goal

Add a narrowly-scoped, conservative cleanup stage for a 1–2 pixel outer halo while preserving real scene edges and textured content.

## New module

Added `src/video/outerHaloSuppress.js` with three public APIs:
- `buildOuterHaloMask`
- `measureOuterHaloResidual`
- `applyOuterHaloSuppression`

### Candidate region

The halo mask only considers pixels whose current alpha is effectively empty (`<= 0.012`) but which lie within a maximum radius of about 2 pixels from a nearby non-trivial alpha source (`>= 0.025`).

This keeps the stage outside the existing watermark body/ring logic instead of broadening the main repair mask.

### Reference construction

For each halo candidate:
- find the nearest nearby alpha source to establish an inward direction
- sample further outward from the watermark footprint at several distances
- add two tangent-offset samples
- use a median luma reference rather than a broad average

The stage rejects samples when the outward references disagree too strongly or when the tangent direction shows a strong real structure.

### Correction

Correction is luma-only in Phase 1:
- default strength is bounded
- per-pixel luma shift is capped
- no chroma repainting
- no blur or texture synthesis
- only low-structure halo candidates can be changed

### Acceptance gates

The stage follows the same try → measure → accept pattern as recent cleanup modules:
1. measure the incoming outer-halo residual
2. generate a candidate
3. remeasure halo residual
4. remeasure existing post-clean residual metrics
5. accept only when the local halo score improves enough and existing total/luma/chroma metrics remain safe
6. otherwise restore the exact incoming image

## Tests

Added `tests/outerHaloSuppress.test.mjs` covering:
1. a smooth gradient with a synthetic thin dark halo just outside the alpha footprint; the halo must be reduced and the candidate accepted
2. a high-detail checkerboard; the stage must back off and preserve the exact input
3. invalid alpha geometry; safe no-op

## Runtime scope

Phase 1 is deliberately standalone. It is **not yet wired into the structured runtime path**.

This mirrors the rollout used for Center Seam and Local Tone Match: validate the isolated algorithm in CI before changing the production stage order.

If Phase 1 is green, the next version can integrate Outer Halo as the final structured finisher after Local Tone Match, with its own diagnostics and explicit opt-out.
