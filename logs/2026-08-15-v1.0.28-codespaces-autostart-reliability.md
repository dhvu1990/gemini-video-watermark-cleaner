# v1.0.28 — Codespaces Auto-start Reliability

Date: 2026-08-15

## Goal
Fix the Codespaces runtime issue found during the first private-port validation without changing the watermark-cleaning algorithm.

## User validation that exposed the issue
The first Codespace was created successfully and port 5173 was forwarded as Private, but the forwarded URL returned HTTP 401 / unavailable because no process was actually listening on 127.0.0.1:5173.

Diagnostics performed in the Codespace:

- `curl -I http://127.0.0.1:5173` failed to connect.
- `/tmp/gemini-vite.log` existed but was empty.
- Starting Vite manually with `npm run dev -- --host 0.0.0.0 --port 5173` succeeded immediately.
- After manual start, the private `*.app.github.dev` URL loaded the full application.
- A real Gemini/Veo sample was uploaded and auto-detection / cleaned preview worked end-to-end inside Codespaces.

Conclusion: application code, dependencies and GitHub private port forwarding were healthy. The failure was isolated to the v1.0.27 lifecycle auto-start command.

## Root cause / risk factors
v1.0.27 used a direct `nohup ... &` command inside `postStartCommand` and configured the forwarded application protocol as HTTPS even though Vite itself serves HTTP. The lifecycle shell could terminate the child process before it became a stable detached service.

## v1.0.28 changes

1. Add `.devcontainer/start-vite.sh`.
2. Launcher first checks `http://127.0.0.1:5173/` and exits if Vite is already healthy.
3. Launcher uses `setsid -f` so Vite runs in a new session independent from the Dev Container lifecycle shell.
4. Launcher redirects output to `/tmp/gemini-vite.log` and performs a bounded health-check after starting.
5. `devcontainer.json` changes port 5173 protocol from `https` to `http`.
6. `postStartCommand` becomes `bash .devcontainer/start-vite.sh`.
7. Codespaces regression tests now verify HTTP protocol, launcher delegation, detached startup and localhost health-check.
8. Runtime/package metadata is bumped to 1.0.28.

## Security posture

- Port 5173 remains forwarded without a committed visibility override.
- Intended Codespaces port visibility remains Private.
- No server-side upload/backend was introduced.
- Video processing remains local in the user's browser.
- Repository remains Public during this validation stage. It must only be switched to Private after v1.0.28 is merged and a fresh Resume/Rebuild confirms automatic startup.

## Validation plan

1. CI syntax/tests/build must pass.
2. Merge to `main` only after CI passes.
3. In the existing Codespace, pull/rebuild or create a fresh Codespace from `main`.
4. Do not run Vite manually.
5. Confirm `curl -I http://127.0.0.1:5173` returns HTTP success after startup.
6. Confirm port 5173 is Private.
7. Open the forwarded URL and run one end-to-end video test.
8. Record the milestone in Google Drive.
9. Create a backup milestone before changing repository visibility to Private.

## Algorithm impact
None. v1.0.28 is an infrastructure/privacy-runtime patch only. The cleaning behavior remains the v1.0.26 algorithm baseline.
