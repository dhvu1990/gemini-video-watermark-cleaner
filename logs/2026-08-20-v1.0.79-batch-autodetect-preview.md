# v1.0.79 — Per-video batch auto-detect previews

Date: 2026-08-20

## Objective

Make multi-video review as informative as the existing single-video Auto Detection Preview so each queued video can be visually assessed before or while batch cleanup is prepared.

The user specifically requested that choosing multiple videos should show a separate auto-detection result for every video, similar to the single-video view that shows candidate identity, match confidence, and zoomed original/cleaned watermark regions.

## User-facing behavior

After `Choose multiple videos`:

1. selected files are still ingested in yielded chunks;
2. a sequential auto-detect pass starts automatically;
3. every batch row expands with its own detection section;
4. the section displays:
   - auto-detected candidate name;
   - confidence/match percentage;
   - cleanup/background mode;
   - detected ROI coordinates and size;
   - anti-streak risk flags when present;
   - `ZOOMED ORIGINAL` watermark ROI;
   - `ZOOMED CLEANED` watermark ROI;
5. the batch summary shows `auto-detect X/N` while analysis is running.

The result is intended to let the operator compare several videos without selecting each file individually in the single-video workflow.

## Automatic analysis strategy

Batch preview detection is deliberately sequential rather than parallel.

Reasons:

- v1.0.78 already established sequential batch work to reduce browser memory pressure;
- parallel frame decoding across many files can consume substantial memory and GPU/decoder resources;
- a single persistent Worker is already used by the hardened batch transport path;
- sequential inspect operations reuse that Worker and therefore retain the v1.0.78 network/worker reliability improvements.

## Cached inspect reuse

The detection result and preview from automatic batch analysis are cached per item.

Stored per item:

- `detection`
- `preview`
- `inspectOptions`
- `autoDetectStatus`
- `autoDetectProgress`
- `autoDetectError`

When `Clean all` later reaches the item, the cached inspect result is reused if these inspect settings still match:

- sample count;
- minimum confidence;
- edge polish;
- scan fraction.

If any relevant setting changed after the preview was generated, the item is inspected again before processing. This avoids silently cleaning from stale detection data.

## Preview contents

The batch UI uses the same `inspectVideo` result already used by the single-video preview.

The retained preview contains small ROI image data rather than a full decoded video frame, so keeping original/cleaned watermark crops for several batch items is substantially lighter than retaining full frames or video canvases.

## New helper module

Added `src/batchPreviewModel.js`.

It provides:

- `humanizeBatchCandidate(...)`
- `batchBackgroundLabel(...)`
- `buildBatchDetectionView(...)`
- `sameBatchInspectOptions(...)`

This keeps display/model logic testable without requiring a browser DOM.

Candidate IDs such as:

`veo-portrait-720-relocated@2`

are rendered as:

`Portrait 720 Relocated`

matching the single-video presentation style.

## Batch UI changes

Updated `src/batch-ui.js`.

### New item state

Each batch item now carries preview/detection state in addition to processing state.

### New automatic pass

`analyzeBatchPreviews(items)` runs automatically for newly added files.

Each item progresses through:

- `pending`
- `analyzing`
- `ready`
- `error`

A preview-analysis error does not permanently make the video uncleanable. The normal `Clean all` path will inspect the item again if no usable cached detection is present.

### Cancel behavior

During the automatic preview pass, `Cancel batch` is also enabled. Cancellation stops the current Worker inspect operation and leaves remaining items available for later cleaning.

### Row rendering

Every batch row now has two levels:

1. file/process row containing filename, progress, and actions;
2. auto-detect section containing detection summary and two ROI canvases.

## Batch layout changes

Updated `src/batch-mount.js` with styles for:

- expanded batch rows;
- detection summary;
- analysis/error states;
- two compact ROI cards;
- desktop/mobile responsive layouts.

The note under the queue now explains that automatic per-file detection happens before `Clean all`, cached detection is reused when settings remain unchanged, and a single worker is reused across the queue with transient network/worker retries.

## Reliability relationship with v1.0.78

This release intentionally builds on rather than replaces v1.0.78.

The automatic preview pass uses the same:

- persistent batch Worker;
- bounded transient transport retry;
- Worker recreation only after transport failure;
- sequential execution policy.

Therefore it does not restore the old behavior of repeatedly creating a fresh module Worker for every individual stage.
