# v1.0.68 — Anti-streak runtime wiring

Date: 2026-08-18

## Goal
Expose the v1.0.67 anti-streak diagnostic summary through the real runtime preview and export metadata without changing pixel behavior.

## Context
v1.0.67 introduced `summarizeAntiStreakDiagnostics()` as a diagnostic-only aggregator. It was not yet called by the engine runtime.

## Files changed
- `src/video/engine.js`
- `tests/antiStreakRuntimeIntegration.test.mjs`
- `package.json`
- `src/version.js`

## Runtime integration
`repairPaddedRegion()` now builds `antiStreakDiagnostics` after the existing edge-bridge and dual-ring stages using:
- `temporalDonorAcceptance`
- the nested temporal donor local-structure diagnostics
- `atlasSummary`
- structured-ring diagnostics emitted by the dual-ring runtime

The summary is returned alongside the existing diagnostics.

`createDetectionPreview()` now exposes the summary as `antiStreak`.

`cleanVideo()` now aggregates diagnostic-only export telemetry:
- number of processed frames with one or more anti-streak risk flags
- count per risk-flag name

## Pixel safety
No image-processing stage was added, removed, reordered, strengthened or weakened. No threshold, mask, donor-selection rule, acceptance formula, atlas parameter, edge-bridge parameter, dual-ring parameter, calibration logic or stabilization strength changed.

The new runtime summary is computed only after the existing pixel work for the padded repair has completed.

## Regression test
`tests/antiStreakRuntimeIntegration.test.mjs` reconstructs the existing no-history repair pipeline manually:
1. inverse alpha restoration
2. edge polish
3. padded texture repair
4. normal edge bridge
5. dual-ring finish

It compares the manual reference against `repairPaddedRegion()` byte-for-byte for both padded output and cropped cleaned output, then verifies that the anti-streak summary is present and well-shaped.
