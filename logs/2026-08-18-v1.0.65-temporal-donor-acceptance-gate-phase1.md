# v1.0.65 — Temporal donor acceptance gate, phase 1

Date: 2026-08-18

## Goal
Add a reusable try/measure/accept/rollback safety layer for temporal donor candidates before runtime integration.

## Why phase 1
The temporal donor path now has a local-structure confidence guard (v1.0.64), but it still lacks a pass-level residual acceptance decision. Importing `measurePostCleanupResidual()` directly into `textureRepair.js` would create an undesirable dependency cycle because `edgeBridge.js` already imports `buildHybridRepairMask()` from `textureRepair.js`.

This version therefore creates a standalone acceptance helper that can be called by the orchestration layer without changing pixel behavior yet.

## Logic
`evaluateTemporalDonorAcceptance(baseline, candidate, alphaMap, options)`:
- detects whether a real temporal candidate was attempted;
- measures baseline and candidate with `measurePostCleanupResidual()`;
- computes total/luma/chroma ratios and total improvement;
- accepts only when residual samples are available and all safety bounds pass;
- otherwise returns the original baseline object unchanged.

Default safety bounds:
- total ratio <= 1.002
- luma ratio <= 1.006
- chroma ratio <= 1.006
- minimum total improvement >= -0.002

These defaults are intentionally near-neutral: the future runtime integration may accept a candidate that is essentially equivalent globally, but rejects material regressions.

## Tests
Regression coverage includes:
1. materially worse temporal donor candidate is rolled back;
2. cleaner candidate inside safety bounds is accepted;
3. no temporal candidate returns the baseline unchanged.
