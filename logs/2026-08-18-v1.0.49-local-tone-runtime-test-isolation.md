# v1.0.49 — Local Tone runtime test isolation fix

## Context

PR #49 (`v1.0.48: wire local tone match into structured runtime`) passed install, alpha setup and syntax checks, but GitHub Actions CI run #549 failed in the test step.

Result:
- 97 tests total
- 96 passed
- 1 failed
- build skipped because tests failed

The only failing test was:
`structured cleanup exposes guarded local-tone diagnostics after center-seam stage`

All standalone Local Tone Match unit tests passed, including smooth-gradient improvement, high-detail checkerboard safety, and invalid-alpha no-op coverage.

## Root cause

The runtime integration test forced `totalThreshold: 999` and `lumaThreshold: 999`, then asserted that `structuredRing.attempted === false`.

That assumption was incomplete because the structured runtime also has a third trigger: `alignedBefore.score >= 1.40` from the shape-aligned ring residual metric. The synthetic offset fixture can legitimately exceed that aligned residual threshold even when the two explicit scalar thresholds are set high.

Therefore `structuredRing.attempted === true` is valid runtime behavior for this fixture. The failure is a test-isolation problem, not a Local Tone Match algorithm failure.

## Fix

Created successor branch `agent/v1.0.49` instead of modifying v1.0.48 in place.

The Local Tone runtime integration test now validates the behavior it actually owns:
- Local Tone diagnostics are exposed and enabled
- the pre-existing Center Seam stage remains explicitly disabled in the fixture
- `acceptedMode` gets `local-tone` only when Local Tone is accepted
- explicit `localToneMatch: false` still disables the stage

The test no longer asserts that the independent structured-ring trigger must be skipped.

## Safety

No production cleanup code, thresholds, strengths or acceptance gates are changed in this correction.

The v1.0.48 runtime ordering remains unchanged:
structured consensus -> structured ring -> micro-salvage -> shape ghost -> center seam -> local tone match.

## Versioning

This corrective edit advances the release candidate to `1.0.49`.
Both `package.json` and `src/version.js` are updated together.
