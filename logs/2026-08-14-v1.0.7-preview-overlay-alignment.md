# v1.0.7 - Preview overlay alignment regression

Date: 2026-08-14

## User-reported symptom

After v1.0.6 auto-detection completed successfully on a portrait Gemini/Veo video, the right-side `ZOOMED ORIGINAL` and `ZOOMED CLEANED` previews clearly contained the correct Gemini diamond watermark region, but the green bounding box shown over the full-frame video preview was visibly offset and appeared near the bottom of the displayed frame instead of over the actual watermark.

The observed auto-detection itself was strong (`Portrait 1080 Inset`, about 88% match), so the discrepancy suggested a visualization coordinate bug rather than a detector-position bug.

## Root cause

`src/main.js` correctly mapped source coordinates to percentages of the source video frame and assigned the source `aspect-ratio` to `#previewStage`.

However, `src/styles.css` also applied:

```css
.video-stage {
  width: 100%;
  min-height: 260px;
  max-height: 680px;
}
```

For a 1080x1920 portrait source, the width-derived source aspect ratio requires a much taller preview stage. The `max-height: 680px` constraint overrode that geometry, so the displayed stage no longer represented the 1080:1920 coordinate space even though the overlay continued to use percentages derived from the 1080x1920 frame.

This caused the visual bounding box to be offset/scaled incorrectly while the detector ROI and cleanup coordinates remained correct.

## Fix

v1.0.7 removes the conflicting min/max height constraints from `.video-stage` and lets the source `aspect-ratio` fully determine the stage geometry.

The video element is positioned absolutely inside that correctly proportioned stage:

```css
.video-stage {
  position: relative;
  width: 100%;
  min-height: 0;
  overflow: hidden;
  display: block;
}

.video-stage video {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  object-fit: contain;
}
```

The watermark overlay remains positioned by source-frame percentages, which now map to an identically proportioned display surface.

## Scope

This release changes preview rendering only.

Unchanged:

- detector candidate geometry,
- multi-frame scoring,
- alpha gain estimation,
- zoomed original ROI,
- zoomed cleaned ROI,
- cleanup/export position,
- inverse-alpha restoration,
- per-frame gating,
- temporal stabilization,
- audio passthrough.

## Expected regression result

For the same portrait test video used against v1.0.6:

1. auto-detection should still identify the same Gemini/Veo watermark candidate;
2. `ZOOMED ORIGINAL` should still show the watermark;
3. `ZOOMED CLEANED` should still show the cleaned ROI;
4. the green full-frame bounding box should now sit directly over the visible Gemini watermark;
5. the preview frame should retain the exact source aspect ratio without vertical compression.
