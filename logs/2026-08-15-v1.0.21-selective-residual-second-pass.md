# v1.0.21 — Selective Residual Second Pass

Date: 2026-08-15

## Context

v1.0.20 was validated against two different real Gemini/Veo videos.

### Case A — textured keyboard / laptop background

Observed values:
- calibration total residual: about 16.500
- post-clean total residual: about 1.446
- post-clean luma residual: about 2.440
- post-clean chroma residual: about 0.836

Visual result:
- overall cleanup was strong,
- recovered texture remained visible,
- but a faint Gemini diamond skeleton / edge structure was still visible on the complex background.

### Case B — smoother blue USB-C background

Observed values:
- calibration total residual: about 9.788
- post-clean total residual: about 0.745
- post-clean luma residual: about 1.114
- post-clean chroma residual: about 0.519

Visual result:
- cleanup was already close to production quality,
- the watermark footprint was faint,
- further aggressive cleanup risked over-processing an already-good result.

## Problem identified

A single fixed finishing strength is no longer appropriate for both cases.

The difficult case benefits from one more conservative cleanup attempt, while the easy case should be left alone.

The existing UI also displayed `Final improvement = 0.0%` even when calibration residual and post-clean residual showed a very large reduction. The displayed metric therefore did not reflect overall cleanup progress.

## Goals

1. Keep v1.0.20 behavior unchanged for low-residual / easy scenes.
2. Allow a second cleanup attempt only when residual evidence says the scene still needs it.
3. Target shape-aligned inner watermark skeletons without blurring the high-alpha core.
4. Reject the second pass automatically when it does not improve the result.
5. Fix the displayed Final improvement metric so it can fall back to calibration residual vs post-clean residual.
6. Preserve local-browser processing, Web Worker execution, detector geometry, subpixel alpha calibration, dual-ring cleanup, temporal atlas and audio passthrough.

## Implementation

### 1. Residual-aware second-pass gate

`applyDualRingLumaFinish()` now runs the existing v1.0.20 primary dual-ring pass first.

The second pass is considered only when either:
- post-primary dual-ring residual >= `1.05`, or
- measured shape-aligned inner-structure score >= `4.0`.

This threshold is intentionally between the two real validation samples:
- USB-C sample: ~0.745 -> skip second pass,
- textured keyboard sample: ~1.446 -> eligible for second pass.

### 2. Inner-structure residual measurement

Added `measureInnerStructureResidual()`.

It looks for image gradients inside the medium-alpha watermark band whose direction strongly aligns with the alpha-map gradient. This is used as a conservative proxy for a remaining Gemini diamond skeleton.

The score is restricted by:
- alpha band,
- hybrid core mask,
- edge mask,
- gradient magnitude,
- gradient-direction alignment.

It is not a general-purpose blur detector and does not trigger simply because the background contains texture.

### 3. Inner-structure breaker

Added a bounded second pass that:
- only touches the medium-alpha / edge-adjacent band,
- uses normal-direction outer + inner anchors,
- corrects luma only,
- limits per-pixel luma correction to +/-10,
- caps blend at 0.24,
- strongly suppresses high-alpha core pixels,
- applies a structure disagreement guard.

### 4. Try-and-reject safety gate

The second pass is not automatically kept.

After generating a candidate result, v1.0.21 measures:
- dual-ring residual after the candidate,
- inner-structure residual after the candidate.

The candidate is accepted only if:
- dual-ring residual improves by at least a small amount, OR inner-structure score improves,
- AND dual-ring residual is not materially worse than the primary result.

If the candidate fails these checks, the output remains the v1.0.20 primary result.

This is the key protection for already-good scenes.

### 5. Final improvement UI fix

`src/calibration-ui.js` now uses the reported cleanup improvement when it is meaningful.

If the reported value is missing or effectively zero, it falls back to:

`(calibration residual - final post-clean residual) / calibration residual`

This makes the UI reflect the actual overall reduction visible in the two real test cases instead of incorrectly showing 0.0%.

### 6. Version metadata

Visible/package version is now `1.0.21`.

The Worker normalizes returned export metadata to `1.0.21`, avoiding a full engine rewrite solely to update an internal metadata literal.

## Regression coverage

Updated `tests/dualRingFinish.test.mjs` with:

1. Existing dual-ring halo reduction and core-preservation regression.
2. Easy low-residual scene regression:
   - second pass must not be attempted.
3. Hard shape-aligned residual regression:
   - second pass must be attempted when explicitly gated,
   - an accepted candidate must improve residual or inner-structure score,
   - a candidate may never be accepted when it materially worsens the primary result.
4. Existing corner/tip-mask regression.

## Expected real-video behavior

### Smooth/easy background

The result should remain essentially v1.0.20 quality because residual < 1.05 prevents the second pass.

### Complex/textured background

The second pass may run. It should reduce the remaining shape-aligned diamond skeleton if it can do so safely. If not, it automatically falls back to the v1.0.20 result.
