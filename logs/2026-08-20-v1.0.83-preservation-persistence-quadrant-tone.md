# v1.0.83 — Preservation-first smooth gating, persistent structured residual cleanup, quadrant tone field

Date: 2026-08-20
Branch: `agent/v1.0.83-original-detail-persistence-tone`
Base: `main` at v1.0.82

## Real-video trigger

The v1.0.82 preview retest showed three remaining classes of failure:

1. `scene5.mp4` remained the release blocker. It was still entering `Smooth background rebuild`, and the cleaned preview lost meaningful dark scene detail.
2. `scene1.mp4` and `scene6.mp4` still showed coherent diamond-shaped structured residuals after the first guarded structured cleanup.
3. `scene3.mp4` and `scene7.mp4` still showed spatially uneven tone footprints, especially a visible darker polygon/diamond region.

`scene2.mp4` and `scene4.mp4` were visually good enough to treat as regression guards, so this release intentionally avoids a global increase in ring strength.

## Design decision

The initial v1.0.83 idea included carrying an untouched original-frame detail reference deeper into the final smooth reconstruction stage. That would require a broader pipeline signature change across preview and export paths. For this iteration, the safer implementation is narrower:

- make entry into smooth rebuild substantially more conservative using the existing pre-rebuild structural analysis;
- keep the existing v1.0.82 post-candidate detail-preservation rollback;
- add a bounded second coherent structured residual pass instead of increasing the main structured-ring strength;
- replace one global local-tone tendency with a four-sector/quadrant-aware tone field.

This is deliberately a preservation-first release. If scene5 still loses detail after retest, the next iteration should promote the original-frame reference into the runtime contract rather than weakening these guards.

## Change 1 — Preservation-first smooth-mode entry gate

File: `src/video/adaptiveFinish.js`

Added `preservationSafeSmooth()`.

A frame is no longer allowed into raw `smooth-rebuild` merely because `analyzeSmoothBackground()` marked it safe. It must also stay inside a tighter preservation envelope based on:

- complexity;
- surface-fit MAE;
- edge density;
- mean gradient;
- mean Laplacian/high-frequency energy;
- core structure density.

Default preservation limits:

- complexity <= 0.31
- surface MAE <= 7.4
- edge density <= 0.075
- mean gradient <= 7.8
- mean Laplacian <= 5.8
- core structure density <= 0.145

When the normal smooth classifier says safe but this stricter envelope fails:

- `rawMode` becomes `structured`;
- `preservationBlocked` is reported;
- the reason is `detail-preservation-entry-guard`;
- the transition is treated as hard unsafe so an existing smooth temporal state cannot hold the destructive mode for an extra frame.

Why: scene5 demonstrates that `dark` or `low-contrast` must not be treated as equivalent to `empty/smooth`.

## Change 2 — Persistent shape-coherent structured micro-pass

File: `src/video/structuredEvidenceRefine.js`

The first shape-coherent pass remains bounded and guarded. When it actually finds/corrects coherent residual pixels, v1.0.83 now performs one optional persistence pass on its output.

Persistence defaults are intentionally smaller than the primary coherent pass:

- strength 0.16;
- minimum alignment 0.60;
- max luma delta 5.5;
- minimum residual 0.78;
- full residual 4.8;
- minimum neighbor residual 0.58;
- tangent distance 1.5 px.

The pass uses the same key safety mechanisms:

- alpha-shape alignment;
- two-sided anchor prediction;
- tangent-neighbor sign coherence;
- anchor disagreement guard;
- tangent scene-structure guard;
- bounded blend and luma delta.

The outer evidence-gated acceptance in `structuredRingSuppress.js` remains unchanged and still decides whether the complete candidate is safe enough to keep.

New diagnostics:

- `persistence.enabled`
- `persistence.attempted`
- `persistence.accepted`
- corrected/coherent/guarded pixel counts
- mean blend
- mean absolute luma delta

Candidate mode can now include `shape-coherent+persistence`.

Why: scene1/scene6 need a second tiny pass only where the first pass already proves a coherent watermark-shaped residual exists. Increasing main ring strength globally would risk scene2/scene4.

## Change 3 — Quadrant-aware local tone field

File: `src/video/localToneMatch.js`

The local-tone system still fits one robust exterior plane, but the residual inside the watermark footprint is now summarized in four spatial sectors:

- top-left;
- top-right;
- bottom-left;
- bottom-right.

Each sector uses a weighted median of valid footprint residual samples. Sparse sectors fall back to the global weighted median.

During correction, the four sector residuals are bilinearly interpolated across the footprint to form a smooth regional tone field. That regional target is then blended with the existing per-pixel local residual target.

New controls/diagnostics:

- `sectorMix` default 0.62;
- `sectorSigned[4]`;
- `sectorSpread`;
- `meanSectorAdaptation`.

Acceptance now evaluates a regional score that considers both global offset and sector spread. Existing global residual safety gates remain in force.

Why: scene3 and especially scene7 do not have a uniform tone error across the entire watermark footprint. A single global offset can leave or create a visible polygonal patch.
