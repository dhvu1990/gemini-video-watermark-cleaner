# v1.0.85 — Protected residual rescue for dense low-gain structured cases

Date: 2026-08-20
Branch: `agent/v1.0.85`
Base: `main` at v1.0.84 commit `810b016e873a3a28890ceb5b5bc656758f97a6a5`

## Real-video trigger

The v1.0.84 seven-scene retest confirmed the preservation changes worked, especially on scene7 where destructive empty-zone flattening was no longer visible. However two structured cases still showed obvious residual watermark geometry:

- scene1: watermark body mostly removed but diamond/ring geometry remained over real horizontal/diagonal scene structure;
- scene6: strong residual diamond/texture imprint remained across much of the footprint.

The preview telemetry for these cases continued to report combinations such as:

- `dense-structured-ring-residual`
- `accepted-structured-low-gain`

The main design constraint for v1.0.85 is therefore: improve cleanup only when the existing structured pipeline has dense residual evidence but achieved little gain, while preserving the scene-edge safety introduced in v1.0.84.

## Design decision

v1.0.85 does **not** increase global structured-ring strength.

Instead it adds one bounded late-stage candidate named `Protected Residual Rescue`. The candidate is only allowed to run after the existing structured stages and only when the incoming aligned structured evidence is dense enough and the prior cleanup improvement remains low.

This avoids pushing scene2, scene4 and scene7 through a stronger global cleanup path.

## New module — `src/video/protectedResidualRescue.js`

The new module provides:

- `measureProtectedResidualField()`
- `applyProtectedResidualRescue()`

### Multi-direction clean-anchor prediction

For each eligible footprint pixel, the module searches four axes:

- horizontal;
- vertical;
- diagonal down-right/up-left;
- diagonal up-right/down-left.

Each axis must supply clean anchors on both sides of the footprint. A per-axis prediction is generated by distance-weighted interpolation between those clean anchors.

The final target uses the median of the valid directional predictions in YCbCr space. This deliberately rejects a single bad donor direction instead of painting a directional streak through the footprint.

### Texture-imprint support

The rescue covers a broader alpha band than the existing ring-only finisher. This lets it reach the mid-body region where scene6 shows a residual diamond texture imprint rather than only a thin edge halo.

The body contribution is still bounded:

- default max blend: 0.38;
- default luma delta cap: 10;
- chroma correction is much smaller than luma correction;
- a body boost is only applied when directional clean-anchor predictions agree.

This is not a blur or full-footprint repaint.

### Scene-edge protection

Every rescue candidate pixel calls `sceneEdgeProtectionAt()` from the v1.0.84 protection module.

Pixels with strong real-scene edge evidence are skipped entirely. Remaining pixels are weighted down in proportion to their scene-edge protection score.

This is specifically intended to keep scene1's real crossing rails/lines while still allowing cleanup in the surrounding watermark-correlated footprint.

### Candidate safety gates

The rescue is try/measure/accept only.

A candidate is accepted only when:

- the protected residual-field score improves by the configured minimum;
- the candidate score is at least 2% lower than the incoming score;
- global total residual stays within +0.3%;
- global luma residual stays within +0.6%;
- global chroma residual stays within +0.4%.

If any gate fails, exact incoming pixels are returned.

## Runtime integration

File: `src/video/structuredRingSuppress.js`

The new rescue runs after:

1. structured consensus;
2. primary ring / micro-salvage;
3. shape ghost suppression;
4. center seam suppression;
5. local tone match;
6. outer halo suppression;
7. evidence-gated structured refinement.

The rescue entry gate requires:

- aligned structured score >= 1.40 by default;
- aligned sample density >= 0.010 by default;
- prior aligned improvement <= 0.12 by default.

This represents the intended `dense residual + low gain` state.

If accepted, `acceptedMode` appends `protected-rescue`.

The structured result now exposes `protectedResidualRescue` diagnostics including:

- attempted / accepted;
- before / after protected residual field;
- candidate and selected global residuals;
- candidate/corrected pixel counts;
- scene-guarded pixels;
- texture-imprint pixels;
- mean accepted blend.

## Diagnostics integration

File: `src/video/structuredRingDiagnostics.js`

Normalized structured diagnostics now expose a `protectedResidualRescue` stage summary so later preview/telemetry work can surface whether the rescue attempted and whether it was accepted.

## Regression coverage

New test file: `tests/protectedResidualRescue.test.mjs`

Coverage includes:

1. a broad diamond-shaped tone imprint on a smooth structured field;
2. a strong real line crossing the footprint, verifying the rescue remains bounded and scene-edge guarded.

The existing v1.0.84 crossing-edge and hard-suppression tests remain untouched and continue to act as regression guards.

## Validation policy

Before merge, GitHub Actions must pass:

- pinned alpha sync;
- `npm run check`;
- `npm test`;
- `npm run build`.

A successful CI run does not prove real-video visual quality. After merge, the same seven source videos must be rerun, with scene6 and scene1 checked first, then scene2/4/7 for preservation regressions.
