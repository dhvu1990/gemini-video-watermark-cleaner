# v1.0.133 — Veo residual micro-finish (private real-video comparison)

## Verified baseline

The user supplied the **original** and **v1.0.132 exported** copies of the same private 1920x1080, 24 fps, 8s (192 frame) Veo video. Files were analyzed locally and are not in this repository.

The text was correctly located and the main bright fill removed by v1.0.132. The remaining defect was **small bright, punctate Veo-shaped ghosting** (especially ~0.5–5.3 seconds) and a mild tonal/texture mismatch in the same ROI. This was visible in the exported video, not just the detector preview. The exported codec also changed general image pixels outside the ROI, so raw full-frame source/export differences are not an accurate watermark-cleanliness measure.

## Bounded implementation

- This release **does not change any Gemini detector, alpha, thresholds, reconstruction or scene-cut code**.
- `veoWordmarkResidualFinish.js` runs only following an accepted Veo-specific reconstruction when the exterior fit is below 26 MAE.
- Require original-versus-first-pass positive RGB overlay evidence in all three letter zones, and significant **letter-aligned positive 5x5 high-pass excess** above local unmarked texture.
- Expand a **3-pixel mask only around confirmed overlay pixels**; use 5px only as the exclusion ring to estimate unmarked texture, never as a repair mask.
- Copy the gradient field from clean texture above the wordmark and solve with the already-clean first pass as the boundary, preserving the original scene outside the mask.
- Bound per-channel change to at most 41; require at least 13% / 0.22 high-pass improvement, small mean changes, and roll back byte-for-byte when acceptance conditions fail.
- The same Veo repair entry point remains wired to preview, single-file export and batch export. The preview note shows when the residual micro-finish was applied.
- Bump `package.json` and `src/version.js` from 1.0.132 to 1.0.133.

## Empirical results (prototype, not production MP4)

An offline Node.js trial on the paired **v1.0.132 encoded ROI** and the original ROI invoked this deterministic micro-finish for every 67x67 sample frame. It applied the optional step on **117/192 frames**. The remaining 75 passed through unchanged because the correlated bright ghost signal did not exceed the local threshold.

On those 117 accepted frames, the mean positive, letter-aligned high-pass response decreased from about **2.59 to 0.92**. Mean change within the modified pixels was about **5.0 per RGB channel**, with no edits outside the bounded mask. Only two active/inactive transitions occurred (near frames 11 and 128); this is observed prototype behavior, not a guarantee of flicker-free output.

A visual montage of early, middle and late ROI frames shows fewer letter-shaped bright pinholes than the v1.0.132 export. In this comparison, the separate Veo/scene donor protection made the result preferable to another aggressive global alpha or blur. The metric only measures the targeted high-pass signature, **not actual ground-truth background accuracy**.

## Remaining gates

- GitHub Actions: `npm run setup:alpha`, `npm run check`, `npm test`, `npm run build`.
- Real browser-based MP4 export under v1.0.133 still needs operator comparison against v1.0.132, especially around 4–6 s and at nearby bright reflections.
- If micro-finish leaves dark blotches, cross-scene edge damage or flicker, hold/rollback and inspect the local donor and dynamic mask instead of lowering global detection thresholds.

No customer video, frames, credential or hidden provenance-removal code is committed.
