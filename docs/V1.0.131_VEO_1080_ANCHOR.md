# v1.0.131 - Veo 1080p text-anchor regression

## Operator report and real-video evidence

The v1.0.130 website displayed a 17% "Possible watermark candidate" that highlighted an unrelated lower-right background detail rather than the visible "Veo" text.

A private, operator-supplied **8 second, 1920x1080, 24 fps** Veo video reproduced the issue. The actual wordmark is near the lower-right corner (visible glyph approximately x=1862..1898, y=1042..1055). The private MP4 and screenshots are not committed.

The existing 720px-relative corner family inflated the glyph stencil and margins on a 1080p frame, which causes its real-wordmark score to miss the 0.36 safety floor. Offline scoring against extracted local source frames using the current alpha-stencil and correlation weighting found:

- Existing over-scaled 79/90/101px wordmark candidates did not align with the target.
- A 67px stencil at ROI x=1848, y=1002 aligns with the real mark.
- At that ROI, confidence was approximately 0.568 (0.35s), 0.564 (0.7s), 0.549 (1.04s), 0.475 (4.5s), and 0.455 (7.5s).
- These local offline scores support detection, not export/cleanup quality.

## Bounded correction

- Add a compact wordmark candidate family based on the shorter frame dimension and a 1080px reference, with sizes 60/67/74 and restricted corner insets.
- Keep every legacy projected candidate intact for alternative Veo layouts and preserve **all** existing score and confidence thresholds.
- Preserve the original Gemini diamond detection, cleanup, calibration, scene-edge guards, preview/export and scene-cut reset paths.
- Add a 1920x1080 geometry regression at x=1848, y=1002, size=67 and a positive multi-frame synthetic detector regression.
- Bump `package.json` and `src/version.js` to 1.0.131; the UI picks up the new version automatically.
